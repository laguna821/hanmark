# HanMark 2.5.3 — Large-document PDF reliability / 대형 문서 PDF 안정화

## English

HanMark 2.5.3 hardens the built-in Editorial PDF path for large and deeply structured notes, and fixes imported BMP rendering in Achmage Editorial HTML. The Markdown source, Kordoc 4.2.5 HWPX engine, reusable HWPX templates, optional Pandoc DOCX path, document imports, CMDS Eagle bridge, and existing command IDs remain unchanged.

### Large-document PDF

- **Oversized code blocks are physically divided into bounded print chunks.** HanMark estimates wrapped print rows and preserves the original code text and line endings instead of asking Chromium to keep one multi-page block together.
- **Tables choose a safe layout without dropping content.** Ordinary multi-page tables remain native tables with repeating headers. Exceptionally tall rows or headers and very wide tables use an ordinary-flow vertical fallback that preserves cell order, full values, and embedded images.
- **Large quotes, callouts, and image-bearing containers can continue across pages.** Short labels remain decorated while oversized bodies flow normally, avoiding impossible keep-together layouts.
- Long headings, paragraphs, lists, nested structures, and multiple images retain their natural pagination. Excessive nesting fails closed with an explicit bounded error instead of a recursive stack overflow.

### Native print reliability

- The print document now uses Obsidian's reserved print-root class, waits for layout to settle, and stays mounted while the operating-system **Save as PDF** step is active. This prevents an apparently normal print dialog from receiving an empty or prematurely removed document.
- A second PDF request is rejected safely while the first print is pending. Orphaned HanMark print roots, styles, and state are cleaned before the next export.
- PDF errors identify the failed stage without echoing the note text, local path, image payload, or private error message.
- The Editorial layout keeps the full-bleed HanMark cover, branded headers, precisely spaced teal rules, one-column body, and actual page numbers introduced on the 2.5.x PDF path.

### Imported BMP images

- Signature-validated BMP data images imported from HWPX now render as images in Achmage Editorial HTML instead of appearing as literal Markdown or base64 text.

### Upgrade notes

- HanMark 2.5.3 requires **Obsidian 1.8.9 or newer** on desktop.
- HWPX, HTML, and PDF require no Python, pypandoc-hwpx, or Pandoc installation.
- Pandoc remains optional and is used only for DOCX generation and the explicitly requested actual DOCX preview.

## 한국어

HanMark 2.5.3은 크고 구조가 복잡한 노트에서도 내장 Editorial PDF가 안정적으로 인쇄되도록 보강하고, HWPX에서 가져온 BMP 이미지가 Achmage Editorial HTML에서 올바르게 표시되도록 수정한 버전입니다. Markdown 원문, Kordoc 4.2.5 HWPX 엔진, 재사용 가능한 HWPX 템플릿, 선택형 Pandoc DOCX 경로, 문서 가져오기, CMDS Eagle 브리지와 기존 명령 ID는 그대로 유지합니다.

### 대형 문서 PDF

- **매우 큰 코드 블록을 제한된 크기의 인쇄 청크로 물리적으로 나눕니다.** 줄바꿈된 인쇄 행 수를 예측하고 원래 코드 문자열과 줄바꿈을 보존해, Chromium이 여러 페이지짜리 블록 하나를 통째로 유지하려다 실패하지 않게 합니다.
- **표는 내용 손실 없이 안전한 배치를 선택합니다.** 일반적인 여러 페이지 표는 머리글을 반복하는 실제 표로 유지합니다. 지나치게 높은 행·머리글이나 매우 넓은 표는 셀 순서, 전체 값과 포함 이미지를 보존하는 일반 흐름의 세로형 대체 배치를 사용합니다.
- **큰 인용·콜아웃과 이미지 포함 컨테이너가 페이지를 이어 흐를 수 있습니다.** 짧은 라벨의 장식은 유지하고 큰 본문은 자연스럽게 나누어, 한 페이지에 함께 넣을 수 없는 구조를 만들지 않습니다.
- 긴 제목·문단·목록, 중첩 구조와 여러 이미지는 자연스러운 쪽 나눔을 유지합니다. 지나친 중첩은 재귀 스택 오류 대신 범위가 제한된 명시적 오류로 안전하게 종료합니다.

### 네이티브 인쇄 안정성

- 인쇄 문서는 Obsidian이 예약한 print-root 클래스를 사용하고 조판이 안정될 때까지 기다리며, 운영체제의 **PDF로 저장** 단계가 진행되는 동안 DOM을 유지합니다. 인쇄 창은 정상적으로 열렸지만 문서가 비거나 너무 일찍 제거되는 문제를 막습니다.
- 첫 PDF 인쇄가 진행 중일 때 두 번째 요청은 첫 작업을 건드리지 않고 안전하게 거절합니다. 다음 내보내기 전에는 남아 있는 HanMark 인쇄 루트·스타일·상태를 정리합니다.
- PDF 오류는 실패한 단계만 알려 주고 노트 본문, 로컬 경로, 이미지 payload나 비공개 원인 메시지를 노출하지 않습니다.
- Editorial 배치는 2.5.x PDF 경로에서 도입한 전면 HanMark 표지, 브랜드 머리말, 정밀한 청록색 실선, 1단 본문과 실제 쪽 번호를 유지합니다.

### 가져온 BMP 이미지

- HWPX에서 가져온 서명 검증 BMP data 이미지가 Achmage Editorial HTML에서 Markdown 또는 base64 글자로 나타나지 않고 실제 이미지로 렌더링됩니다.

### 업데이트 참고

- HanMark 2.5.3은 데스크톱 **Obsidian 1.8.9 이상**이 필요합니다.
- HWPX·HTML·PDF에는 Python, pypandoc-hwpx 또는 Pandoc 설치가 필요하지 않습니다.
- Pandoc은 DOCX 생성과 사용자가 명시적으로 요청한 실제 DOCX 미리보기에만 선택적으로 사용합니다.

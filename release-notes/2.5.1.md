# HanMark 2.5.1 — Reliable images & CMDS Eagle bridge / 안정적인 이미지·CMDS Eagle 연동

## English

HanMark 2.5.1 is a focused reliability update for image-heavy Markdown and
imported HWP/HWPX documents. It preserves the Kordoc 4.2.5 HWPX engine,
templates, Achmage Editorial and Classic HTML themes, optional Pandoc DOCX,
Obsidian PDF delegation, toolbar editing, and existing command IDs.

### Fixed

- Markdown image paths containing Korean text, `%20`, spaces, escaped
  characters, angle destinations, and balanced parentheses are no longer
  truncated. Imported images now remain available in live HWPX preview and
  HWPX, DOCX, and HTML export.
- Large embedded HTML images no longer pass through giant string spreading or
  full-payload regular-expression captures, fixing Electron-dependent
  `Maximum call stack size exceeded` failures.
- **Show in folder** recognizes Windows Explorer's handoff exit behavior only
  for that fixed launcher. Every other external process keeps the existing
  strict success rule.

### CMDS Eagle active cloud / optional Cloudflare R2 fallback

Imported images can now use one of three destinations:

- Vault attachments (default)
- CMDS Eagle's active cloud provider
- Ask on every import

The cloud path prefers a public, credential-free CMDS Eagle workspace bridge.
With current CMDS Eagle versions, HanMark activates the new note, invokes the
registered `cmds-eagle:convert-all-to-cloud` command, and verifies that each
staged local image URL became HTTPS. HanMark does not inspect CMDS Eagle's
plugin object, `data.json`, API key, or private settings.

The compatibility command runs on a disposable note containing each unique
image source once, not on the imported document. The staging note is checked
again at the exact command boundary, and only verified HTTPS replacements are
patched into a fresh read of the imported Markdown. After an event or command
upload has been dispatched, HanMark will not cascade an unresolved image into
another uploader, preventing accidental duplicate objects when a response or
local rewrite is delayed.

If that bridge is unavailable, an optional direct fallback can use a
user-entered HTTPS Worker URL and Public URL. The API key is requested only
when needed, retained in memory only after a successful authenticated upload,
and never saved by HanMark. Authentication failures clear the in-memory key so
it can be corrected on the next attempt. A failed cloud conversion keeps the
safe local image instead of losing it.

### Upgrade notes

- No Python or pypandoc-hwpx is required.
- Pandoc remains optional and is used only for DOCX generation and the
  explicitly requested actual DOCX preview.
- Existing imports whose referenced image files are already missing cannot be
  reconstructed from Markdown alone; reimport the original document after
  updating HanMark.

## 한국어

HanMark 2.5.1은 이미지가 많은 Markdown과 HWP/HWPX 가져오기의 안정성을
집중적으로 높인 업데이트입니다. Kordoc 4.2.5 HWPX 엔진, 템플릿,
Achmage Editorial·Classic HTML, 선택적 Pandoc DOCX, Obsidian PDF 위임,
툴바 편집과 기존 명령 ID는 그대로 유지합니다.

### 수정

- 한글, `%20`, 공백, 이스케이프 문자, 꺾쇠 목적지와 균형 괄호가 섞인
  Markdown 이미지 경로를 더 이상 중간에서 자르지 않습니다. 불러온 이미지는
  HWPX 라이브 미리보기와 HWPX·DOCX·HTML 내보내기까지 이어집니다.
- 대형 내장 HTML 이미지를 거대한 문자 배열로 펼치거나 전체 payload 정규식
  캡처로 처리하지 않아 Electron 환경의 `Maximum call stack size exceeded`
  오류를 수정했습니다.
- **파일 위치 보기**는 고정된 Windows Explorer 실행기의 전달 완료 동작만
  허용합니다. 다른 외부 프로세스는 기존의 엄격한 성공 판정을 유지합니다.

### CMDS Eagle 현재 클라우드 / 선택적 Cloudflare R2 폴백

문서에서 꺼낸 이미지 저장 방식을 세 가지 중 선택할 수 있습니다.

- Vault 첨부 파일(기본)
- CMDS Eagle 현재 클라우드
- 가져올 때마다 묻기

클라우드 경로는 자격증명을 공유하지 않는 공개 CMDS Eagle 워크스페이스
브리지를 우선 사용합니다. 현재 CMDS Eagle에서는 서로 다른 이미지 링크를
한 번씩만 담은 전용 임시 스테이징 노트에서 등록 명령
`cmds-eagle:convert-all-to-cloud`를 실행한 뒤, 검증된 HTTPS URL만 최신
가져오기 Markdown에 적용합니다. 따라서 CMDS가 문서 본문을 다시 쓰거나
반복 참조 이미지를 여러 번 업로드하지 않습니다. HanMark는 CMDS Eagle의
플러그인 객체, `data.json`, API 키 또는 비공개 설정을 읽지 않습니다.

브리지를 사용할 수 없을 때는 사용자가 입력한 HTTPS Worker URL과 Public
URL로 선택적 직접 폴백을 사용할 수 있습니다. API 키는 필요할 때만 묻고
인증 업로드 성공 뒤 현재 Obsidian 세션의 메모리에만 두며 HanMark가
저장하지 않습니다. 인증이 거절되면 키를 지우고 한 번만 다시 입력받습니다.
클라우드 변환이 실패해도 이미지는 안전한 로컬 링크로 남겨 유실하지 않습니다.

### 업데이트 참고

- Python과 pypandoc-hwpx는 필요하지 않습니다.
- Pandoc은 DOCX 생성과 사용자가 직접 요청한 실제 DOCX 미리보기에만
  선택적으로 사용합니다.
- 기존 노트가 참조하던 이미지 파일 자체가 이미 사라진 경우 Markdown
  문법 수정만으로 픽셀을 복구할 수 없습니다. HanMark 업데이트 후 원본
  문서를 다시 가져오세요.

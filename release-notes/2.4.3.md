# HanMark 2.4.3 — Community review hardening / 자동심사 안전성 개선

## English

HanMark 2.4.3 is a compatibility-preserving safety and maintainability update to 2.4.2. HWPX generation, embedded remote/Vault images, semantic templates, toolbar editing, HTML export, and optional Pandoc DOCX export remain available. The built-in HWPX engine stays pinned exactly to Kordoc 4.2.5.

### Community review hardening

- Replaced the old untyped compatibility runtime with typed modules and enabled the complete Obsidian/TypeScript safety rule set.
- Moved imports, Vault writes, export saves, and source-round-trip caching to Obsidian and browser file APIs. Runtime Node filesystem access is no longer used.
- Preserved the existing `hwp-source-*` frontmatter contract and added optional `hwp-source-cache`. Older imported notes ask you to reselect and verify the source once before caching it.
- Removed dynamic JavaScript evaluation, clipboard access, and CSS forced-priority declarations.
- Kept Sharp, ONNX, PDFium, OCR/ML, and other optional native modules out of installation and the startup bundle.
- Overrode the vulnerable optional transitive versions reported against 2.4.2; the shipped dependency audit runs with development and optional modules excluded.
- Added Windows/macOS verification, a release-blocking Community gate, exact three-file publishing, and GitHub artifact attestations.
- Retained the searchable installed/custom Word font catalog. Installed-font discovery and TTF/OTF/TTC/WOFF/WOFF2 file or folder access occur only after the user clicks the corresponding button; selected font bytes are stored in a private content-addressed preview cache.
- Restored the actual Pandoc-generated DOCX package preview with `docx-preview` 0.4.0. Opening a view, typing, changing the active note, or changing a template only marks the result stale; Pandoc runs only after **Refresh** or direct mode selection.
- Restored the 2.4.2 resizable Word template workspace, unsaved-change protection, style links, toolbar palettes, native color pickers, checklist/callout/script controls, and live HWPX preview switch.

### Capability disclosure

- HWPX and HTML need no external executable.
- A user-configured Pandoc executable can run only after an explicit DOCX export, Fast DOCX **Refresh**, or direct preview-mode selection. View opening, typing, active-note changes, and template changes never start Pandoc automatically.
- Optional Word-to-PDF preview can invoke Microsoft Word only after the user requests that preview on Windows.
- HTTP(S) requests occur only for image URLs explicitly present in the note being previewed or exported.
- Files are read only from the Vault, from the private source cache, or from a file explicitly selected by the user. The original HWP/HWPX is never overwritten.
- There are no accounts, analytics, telemetry, advertisements, payments, remote feature flags, or clipboard access.

The optional Pandoc/Word path is intentionally retained and can still be displayed by automated review as a shell-execution disclosure. Remote-image access is limited to URLs explicitly present in the document and runs only for a user-requested preview or export.

### Updating from 2.4.2

No HWPX template migration is required. Existing settings and command IDs are preserved. Notes imported before 2.4.3 may ask you to reselect their original source the first time you create a source-preserving modified copy. If a custom Word preview font was registered by filesystem path in 2.4.2, select that font file once in 2.4.3 so HanMark can create the safer private preview copy; its family name and document template remain intact.

Release assets are exactly:

- `main.js`
- `manifest.json`
- `styles.css`

## 한국어

HanMark 2.4.3은 2.4.2의 기능을 유지하면서 안전성과 유지보수성을 정리한 업데이트입니다. HWPX 생성, 원격·Vault 이미지 포함, 문서 스타일 템플릿, 툴바 편집, HTML, 선택적 Pandoc DOCX를 그대로 사용할 수 있습니다. 내장 HWPX 엔진은 정확히 Kordoc 4.2.5로 유지합니다.

### Community 자동심사 개선

- 타입이 없던 구 호환 런타임을 타입 모듈로 교체하고 Obsidian·TypeScript 안전 규칙 전체를 활성화했습니다.
- 가져오기, Vault 쓰기, 결과 파일 저장과 원본 왕복 캐시를 Obsidian·브라우저 파일 API로 옮겨 런타임 Node 파일 시스템 직접 접근을 제거했습니다.
- 기존 `hwp-source-*` 프런트매터 계약을 유지하고 선택적인 `hwp-source-cache`를 추가했습니다. 예전에 가져온 노트는 처음 한 번 원본을 다시 선택해 검증한 뒤 캐시합니다.
- 동적 JavaScript 실행, 클립보드 접근과 CSS 강제 우선순위를 제거했습니다.
- Sharp, ONNX, PDFium, OCR·ML 등 Kordoc 선택적 네이티브 모듈은 설치와 시작 번들에서 계속 제외합니다.
- 2.4.2에서 보고된 취약한 선택적 전이 의존성 버전을 안전한 버전으로 고정하고, 배포 의존성 감사에서는 개발·선택 모듈을 제외한 실제 배포 표면을 검사합니다.
- Windows·macOS 검증, Release 차단형 Community 게이트, 정확한 세 파일 발행과 GitHub artifact attestation을 추가했습니다.
- 설치·사용자 Word 글꼴 검색을 유지했습니다. 설치 글꼴 검색과 TTF/OTF/TTC/WOFF/WOFF2 파일·폴더 접근은 사용자가 해당 버튼을 누른 뒤에만 실행되며, 선택한 글꼴 데이터는 콘텐츠 해시 기반 비공개 미리보기 캐시에 저장합니다.
- `docx-preview` 0.4.0으로 Pandoc이 실제로 만든 DOCX 패키지 미리보기를 복원했습니다. 뷰 열기, 입력, 활성 노트 변경, 템플릿 변경은 결과를 오래된 상태로 표시할 뿐이며 Pandoc은 **새로 고침** 또는 사용자의 직접적인 모드 선택 뒤에만 실행됩니다.
- 2.4.2의 크기 조절 가능한 Word 템플릿 작업창, 미저장 변경 보호, 스타일 연결, 툴바 팔레트, 네이티브 색상 선택기, 체크·콜아웃·첨자 도구와 실시간 HWPX 미리보기 스위치를 복원했습니다.

### 접근 기능 공개

- HWPX와 HTML에는 외부 실행 파일이 필요하지 않습니다.
- 사용자가 지정한 Pandoc은 명시적인 DOCX 내보내기, 빠른 DOCX **새로 고침**, 또는 사용자가 직접 미리보기 방식을 선택한 뒤에만 실행됩니다. 뷰 열기, 입력, 활성 노트 변경과 템플릿 변경은 Pandoc을 자동 실행하지 않습니다.
- Windows의 선택적 Word-to-PDF 미리보기는 사용자가 요청한 뒤에만 Microsoft Word를 호출할 수 있습니다.
- HTTP(S) 요청은 미리보기나 내보내기 대상 노트에 사용자가 넣은 이미지 URL을 가져올 때만 발생합니다.
- 파일은 Vault, 비공개 원본 캐시 또는 사용자가 직접 선택한 파일에서만 읽습니다. 원본 HWP/HWPX를 덮어쓰지 않습니다.
- 계정, 분석, 텔레메트리, 광고, 결제, 원격 기능 플래그와 클립보드 접근이 없습니다.

선택적인 Pandoc/Word 기능은 의도적으로 유지하므로 자동심사에서 셸 실행 공개 항목 하나가 계속 표시될 수 있습니다. 원격 이미지 접근은 문서에 직접 적힌 URL로 제한되며 사용자가 미리보기나 내보내기를 요청했을 때만 실행됩니다.

### 2.4.2에서 업데이트

HWPX 템플릿 마이그레이션은 필요하지 않습니다. 기존 설정과 명령 ID를 유지합니다. 2.4.3 이전에 가져온 노트는 처음으로 원본 형식 보존 수정본을 만들 때 원본 파일을 한 번 다시 선택하라는 안내가 나올 수 있습니다. 2.4.2에서 파일 시스템 경로로 사용자 Word 미리보기 글꼴을 등록했다면 2.4.3에서 해당 글꼴 파일을 한 번 선택해 더 안전한 비공개 미리보기 사본을 만들어야 합니다. 글꼴명과 문서 템플릿은 그대로 유지됩니다.

Release에는 다음 세 파일만 첨부됩니다.

- `main.js`
- `manifest.json`
- `styles.css`

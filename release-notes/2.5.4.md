# HanMark 2.5.4 — Theme-independent Editorial PDF / 테마 독립형 Editorial PDF

## English

HanMark 2.5.4 makes the built-in Editorial PDF palette independent of Obsidian's current light or dark theme. A document exported from dark mode now uses the same white paper, dark body text, navy and teal accents, borders, code surfaces, and highlights as one exported from light mode.

### Theme-independent Editorial PDF

- The PDF print root establishes its own light color scheme and fixed Editorial palette instead of inheriting Obsidian theme colors.
- Body text, emphasis, links, list markers, inline and block code, tables, quotes, callouts, decorations, and images receive scoped print rules.
- Theme-provided filters, opacity, shadows, and inherited semantic colors cannot tint or dim PDF images and content.
- User-authored inline text and background colors are normalized to the Editorial PDF palette. The same Markdown therefore produces deterministic colors across themes and computers.
- HTML keeps its supported explicit colors. HWPX and DOCX behavior is unchanged.

### Reliability and compatibility

- The 2.5.3 large-document safeguards remain intact: bounded code splitting, adaptive table pagination, ordinary-flow fallbacks for exceptionally large structures, bounded nesting, and privacy-safe stage diagnostics.
- The full-bleed HanMark cover, branded headers, precisely spaced teal rules, one-column body pages, and actual page numbers remain unchanged.
- The native print document remains mounted through the operating-system **Save as PDF** step, rejects concurrent requests safely, and cleans stale print state before the next export.
- Markdown is not rewritten. Kordoc 4.2.5 HWPX generation, reusable templates, optional Pandoc DOCX, document import, CMDS Eagle integration, Achmage Editorial HTML, and existing command IDs remain available.

### Upgrade notes

- HanMark 2.5.4 requires desktop **Obsidian 1.8.9 or newer**.
- HWPX, HTML, and PDF require no Python, pypandoc-hwpx, or Pandoc installation.
- Pandoc remains optional and is used only for DOCX generation and the explicitly requested actual DOCX preview.

## 한국어

HanMark 2.5.4는 내장 Editorial PDF 팔레트를 현재 Obsidian 라이트·다크 테마와 완전히 분리합니다. 이제 다크 모드에서 내보내도 라이트 모드와 동일한 흰색 지면, 어두운 본문, 남색·청록색 강조, 테두리, 코드 배경과 하이라이트로 PDF가 출력됩니다.

### 테마 독립형 Editorial PDF

- PDF 인쇄 루트가 Obsidian 테마 색상을 상속하지 않고 독립적인 라이트 색상 체계와 고정 Editorial 팔레트를 사용합니다.
- 본문·강조·링크·목록 기호·인라인 및 블록 코드·표·인용·콜아웃·장식·이미지에 범위가 제한된 인쇄 규칙을 적용합니다.
- 테마가 제공하는 필터, 투명도, 그림자와 상속 의미 색상이 PDF 이미지와 내용을 물들이거나 어둡게 만들지 않습니다.
- 사용자가 지정한 인라인 글자색과 배경색은 Editorial PDF 표준 팔레트로 정규화합니다. 같은 Markdown은 테마와 컴퓨터가 달라도 결정론적인 색상으로 출력됩니다.
- HTML에서 지원하던 명시적 색상은 계속 작동합니다. HWPX와 DOCX 동작은 바뀌지 않습니다.

### 안정성과 호환성

- 2.5.3의 대형 문서 보호 기능을 그대로 유지합니다. 큰 코드 제한 분할, 표 자동 쪽 나눔, 매우 큰 구조의 일반 흐름 대체 배치, 중첩 범위 제한과 개인정보를 노출하지 않는 단계별 진단이 계속 작동합니다.
- 전면 HanMark 표지, 브랜드 머리말, 정밀한 청록색 실선, 1단 본문과 실제 쪽 번호도 그대로 유지합니다.
- 운영체제의 **PDF로 저장** 단계가 끝날 때까지 네이티브 인쇄 문서를 유지하고, 중복 요청을 안전하게 거절하며, 다음 내보내기 전에 남은 인쇄 상태를 정리합니다.
- Markdown 원문은 다시 쓰지 않습니다. Kordoc 4.2.5 HWPX 생성, 재사용 템플릿, 선택형 Pandoc DOCX, 문서 가져오기, CMDS Eagle 연동, Achmage Editorial HTML과 기존 명령 ID를 계속 사용할 수 있습니다.

### 업데이트 참고

- HanMark 2.5.4는 데스크톱 **Obsidian 1.8.9 이상**이 필요합니다.
- HWPX·HTML·PDF에는 Python, pypandoc-hwpx 또는 Pandoc 설치가 필요하지 않습니다.
- Pandoc은 DOCX 생성과 사용자가 명시적으로 요청한 실제 DOCX 미리보기에만 선택적으로 사용합니다.

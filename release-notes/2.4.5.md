# HanMark 2.4.5 — Preview & Migration / 미리보기·마이그레이션

## English

HanMark 2.4.5 makes Fast DOCX Preview immediate and predictable, and changes document import to a Markdown-first migration workflow. HWPX generation, embedded remote/Vault images, semantic templates, toolbar editing, DOCX/HTML/PDF export, existing command IDs, and the optional Pandoc path remain available. The built-in HWPX engine stays pinned exactly to Kordoc 4.2.5.

### One-click, one-shot DOCX preview

- Opening Fast DOCX Preview explicitly from a HanMark button or command now shows the semantic browser preview immediately.
- That same explicit request upgrades the view exactly once to the actual Pandoc-generated DOCX package when Pandoc is available.
- **Refresh** and direct preview-mode selection remain explicit ways to request a new actual package.
- Workspace restoration and view lifecycle events never start Pandoc. Typing marks the result as changed; active-document and template changes refresh only the in-process semantic preview.
- If Pandoc or DOCX rendering is unavailable, the semantic preview remains visible and the compact status reports the fallback.
- Actual DOCX pages fit the available pane while retaining page proportions and pagination. Very narrow panes use a bounded minimum scale and horizontal scrolling instead of clipping the paper.

This keeps the executable boundary user initiated while removing the extra refresh that previously made a newly opened preview feel incomplete.

### Markdown-first document import

- HWP, HWPX, PDF, DOCX, XLSX, and XLS imports now create ordinary Markdown body content.
- Extracted images are still saved through Obsidian's attachment policy, and Markdown links are still rewritten to their real Vault paths.
- New imports no longer prepend HanMark `hwp-source-*` YAML or a generated source-path callout.
- New imports no longer retain a private copy of the original solely for a later source round trip.
- Real parse, attachment, and batch-import warnings remain visible; only HanMark-generated provenance text is removed from the note body.

HanMark therefore treats imported office documents as material migrating into a Markdown editing system, not as hidden round-trip containers.

### Legacy source-patching compatibility

- Source-preserving patching is removed from the public HWPX export types and export-center options.
- Compatible notes imported by an earlier HanMark release can still use the command-palette-only **고급·레거시: 원본 형식 보존 수정본 만들기** command.
- The legacy path still writes a separate modified copy and never overwrites the original HWP/HWPX.
- A separate migration command creates a clean Markdown sibling from HanMark's older generated source metadata while preserving user-authored YAML and ordinary callouts.

No conversion engine or existing core export workflow is removed. The legacy source-patching entry point is relocated so the default interface reflects HanMark's Markdown-first direction.

### Community review cleanup

- Removed an unnecessary `FontFaceSet` type assertion without changing custom-font loading, caching, or preview behavior.
- Added no dependency, background executable, telemetry, account, advertising, or payment feature.
- Pandoc remains optional and runs only after an explicit DOCX export or preview request.
- OCR/ML native extras remain outside the startup bundle.

### Upgrade notes

No HWPX or Word template migration is required. Existing template libraries, toolbar settings, and command IDs remain compatible. New imports are deliberately clean Markdown; older imported notes keep their existing metadata until the user chooses the migration command. Pandoc is still needed only for DOCX conversion and the actual DOCX preview. HWPX, HTML, and native Obsidian PDF export do not use the Pandoc path.

## 한국어

HanMark 2.4.5는 빠른 DOCX 미리보기를 즉시 이해할 수 있는 동작으로 바꾸고, 문서 가져오기를 Markdown 우선 마이그레이션 절차로 전환한 업데이트입니다. HWPX 생성, 원격·Vault 이미지 포함, 문서 스타일 템플릿, 툴바 편집, DOCX·HTML·PDF 내보내기, 기존 명령 ID와 선택적 Pandoc 경로는 그대로 사용할 수 있습니다. 내장 HWPX 엔진은 정확히 Kordoc 4.2.5로 유지합니다.

### 한 번 열면 한 번 생성되는 DOCX 미리보기

- HanMark 버튼이나 명령으로 빠른 DOCX 미리보기를 직접 열면 문서 스타일 기반 간이 미리보기를 즉시 표시합니다.
- 같은 사용자 요청에서 Pandoc을 사용할 수 있으면 실제로 생성한 DOCX 패키지로 정확히 한 번 전환합니다.
- **새로 고침**과 미리보기 방식 직접 선택은 실제 패키지를 다시 요청하는 명시적인 동작으로 유지합니다.
- 작업공간 복원과 뷰 생명주기 이벤트는 Pandoc을 실행하지 않습니다. 입력은 결과를 `변경됨`으로 표시하고, 활성 문서와 템플릿 변경은 프로세스 없는 간이 미리보기만 갱신합니다.
- Pandoc 또는 DOCX 렌더링을 사용할 수 없어도 간이 미리보기는 남고 작은 상태 표시에서 전환 사유를 안내합니다.
- 실제 DOCX 페이지는 쪽 비율과 페이지 구분을 유지하면서 사용 가능한 패널에 맞춰집니다. 아주 좁은 패널에서는 종이를 자르지 않고 제한된 최소 축척과 가로 스크롤을 사용합니다.

이 방식은 실행 파일 호출을 사용자의 명시적인 동작 안에만 두면서, 처음 연 뒤 새로 고침을 한 번 더 눌러야 했던 불편을 없앱니다.

### Markdown 우선 문서 가져오기

- HWP·HWPX·PDF·DOCX·XLSX·XLS 가져오기는 이제 일반 Markdown 본문을 만듭니다.
- 추출된 이미지는 계속 Obsidian 첨부 정책에 따라 저장하며 Markdown 링크를 실제 Vault 경로로 다시 씁니다.
- 새 가져오기 노트 앞에 HanMark `hwp-source-*` YAML이나 생성된 원본 경로 콜아웃을 붙이지 않습니다.
- 나중의 원본 왕복만을 위해 원본의 비공개 사본을 보관하지 않습니다.
- 실제 파싱·첨부·일괄 가져오기 경고는 계속 표시하며, 노트 본문에서 사라지는 것은 HanMark가 자동 생성했던 출처 문구뿐입니다.

따라서 HanMark는 가져온 오피스 문서를 숨은 왕복 컨테이너가 아니라 Markdown 편집 시스템으로 이주하는 자료로 취급합니다.

### 레거시 원본 수정 호환

- 공개 HWPX 내보내기 타입과 내보내기 센터 옵션에서 원본 형식 보존 수정을 제거했습니다.
- 이전 HanMark 버전으로 가져온 호환 노트에는 명령 팔레트 전용 **고급·레거시: 원본 형식 보존 수정본 만들기**를 계속 제공합니다.
- 레거시 경로도 항상 별도 수정본을 쓰며 원본 HWP/HWPX를 덮어쓰지 않습니다.
- 별도의 마이그레이션 명령은 사용자가 작성한 YAML과 일반 콜아웃을 보존하면서 예전 HanMark 생성 원본 메타데이터만 제거한 깨끗한 Markdown 형제 노트를 만듭니다.

변환 엔진이나 기존 핵심 내보내기 기능을 제거한 것은 아닙니다. 기본 화면이 HanMark의 Markdown 우선 방향을 정확히 보여주도록 레거시 원본 수정 진입점만 옮겼습니다.

### Community 심사 정리

- 사용자 글꼴 로딩·캐시·미리보기 동작을 바꾸지 않으면서 불필요한 `FontFaceSet` 타입 단언을 제거했습니다.
- 새 의존성, 백그라운드 실행 파일, 텔레메트리, 계정, 광고와 결제 기능을 추가하지 않았습니다.
- Pandoc은 계속 선택 사항이며 사용자가 DOCX 내보내기 또는 미리보기를 직접 요청한 뒤에만 실행됩니다.
- OCR·ML 네이티브 선택 모듈은 시작 번들에서 계속 제외합니다.

### 업데이트 안내

HWPX나 Word 템플릿 마이그레이션은 필요하지 않습니다. 기존 템플릿 라이브러리, 툴바 설정과 명령 ID를 유지합니다. 새 가져오기는 의도적으로 깨끗한 Markdown을 만들며, 예전에 가져온 노트의 메타데이터는 사용자가 마이그레이션 명령을 선택할 때까지 그대로 둡니다. Pandoc은 DOCX 변환과 실제 DOCX 미리보기에만 계속 필요합니다. HWPX·HTML·Obsidian 기본 PDF 내보내기는 Pandoc 경로를 사용하지 않습니다.

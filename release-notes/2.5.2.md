# HanMark 2.5.2 — Editorial export reliability / 편집형 내보내기 안정화

## English

HanMark 2.5.2 makes the last step of exporting more predictable without
changing the Markdown source. It keeps the Kordoc 4.2.5 HWPX engine, image
embedding, reusable HWPX templates, optional Pandoc DOCX path, document
imports, CMDS Eagle bridge, and existing command IDs from 2.5.1.

### Editorial HTML and PDF

- **Achmage Editorial HTML now uses a shared semantic document model.** Soft
  line breaks are normalized instead of becoming accidental vertical gaps,
  while headings, nested lists, tasks, tables, quotes, callouts, code, links,
  wiki links, and images retain their document meaning.
- **Raw HTML is handled explicitly.** Safe inline and block markup is
  normalized; scripts, event handlers, unsafe URLs, and unsupported subtrees
  are not copied into the exported document. The selectable **Classic** HTML
  theme keeps its previous compatibility behavior.
- **Editorial PDF is built in.** It uses the same normalized document model
  and Chromium print pipeline: an A4 filename-only cover, then the filename in
  the header, top and bottom rules, and the actual page number from page 2.
- PDF opens the operating system print dialog, where the user chooses
  **Save as PDF** and the destination. It does not require Pandoc and does not
  invoke Obsidian's previous generic PDF-export command.
- PDF image preparation is fail-closed. HanMark asks the user to retry or
  cancel instead of printing a document with silently missing images.
- Pretendard weights 400 and 600 are embedded in `styles.css`, adding roughly
  2 MB to the plugin stylesheet so Editorial PDF typography is deterministic
  without a separately installed font.

### Reliability

- **Show in folder** now launches Windows Explorer as a visible non-blocking
  handoff and selects the saved file. Converter processes retain their strict
  exit and timeout handling.
- Imported images can use a user-selected Vault-relative folder. HanMark skips
  extracted images absent from the imported Markdown and, after verified CMDS
  cloud replacement, removes only unchanged temporary files it created.
- The Markdown source is never rewritten by HTML or PDF export.
- Existing Vault, CMDS Eagle active-cloud, ask-every-import, and optional
  direct R2 image destinations are preserved.

### Upgrade notes

- HanMark 2.5.2 requires **Obsidian 1.8.9 or newer** on desktop.
- HWPX, HTML, and PDF need no Python, pypandoc-hwpx, or Pandoc installation.
- Pandoc remains optional and is used only for DOCX generation and the
  explicitly requested actual DOCX preview.

## 한국어

HanMark 2.5.2는 Markdown 원문을 바꾸지 않으면서 내보내기의 마지막 단계를
더 예측 가능하게 다듬은 버전입니다. 2.5.1의 Kordoc 4.2.5 HWPX 엔진,
이미지 포함, 재사용 가능한 HWPX 템플릿, 선택형 Pandoc DOCX 경로, 문서
가져오기, CMDS Eagle 브리지와 기존 명령 ID는 그대로 유지합니다.

### 편집형 HTML과 PDF

- **Achmage Editorial HTML이 공통 의미 구조를 사용합니다.** 소프트 줄바꿈은
  뜻하지 않은 세로 공백이 되지 않도록 정규화하고, 제목·중첩 목록·할 일·
  표·인용·콜아웃·코드·링크·위키 링크·이미지의 문서 의미는 보존합니다.
- **원시 HTML을 명시적으로 처리합니다.** 안전한 인라인·블록 마크업은
  정규화하고, 스크립트·이벤트 핸들러·안전하지 않은 URL과 지원하지 않는
  하위 구조는 결과물에 복사하지 않습니다. 선택 가능한 **Classic** HTML
  테마는 이전 호환 동작을 유지합니다.
- **Editorial PDF를 내장했습니다.** HTML과 같은 정규화 문서 구조와 Chromium
  인쇄 파이프라인을 사용해 A4 첫 장에는 파일명만 표시하고, 2쪽부터는
  파일명 머리말·위아래 실선·실제 쪽 번호를 넣습니다.
- PDF는 운영체제 인쇄 창을 열며, 사용자가 **PDF로 저장**과 위치를 선택합니다.
  Pandoc이 필요하지 않고 이전의 일반 Obsidian PDF 내보내기 명령도 호출하지
  않습니다.
- PDF 이미지 준비는 실패 폐쇄 방식입니다. 이미지가 조용히 빠진 문서를
  인쇄하지 않고 재시도 또는 취소를 선택하게 합니다.
- Pretendard 400·600 굵기를 `styles.css` 안에 포함했습니다. 별도 글꼴 설치
  없이 Editorial PDF의 글꼴을 일정하게 유지하는 대신 플러그인 스타일시트
  용량이 약 2 MB 늘어납니다.

### 안정성

- **파일 위치 보기**는 Windows Explorer를 보이는 비차단 방식으로 실행해
  저장한 파일을 선택합니다. 변환기 프로세스의 엄격한 종료코드·시간 제한
  처리는 그대로 유지합니다.
- 가져온 이미지는 사용자가 정한 Vault 상대 폴더에 둘 수 있습니다. 가져온
  Markdown에서 참조하지 않는 추출 이미지는 저장하지 않고, CMDS 클라우드
  교체를 검증한 뒤에는 HanMark가 만든 변경되지 않은 임시 파일만 정리합니다.
- HTML 또는 PDF 내보내기가 Markdown 원문을 다시 쓰지 않습니다.
- Vault, CMDS Eagle 현재 클라우드, 가져올 때마다 묻기, 선택형 직접 R2 이미지
  저장 방식은 모두 유지합니다.

### 업데이트 참고

- HanMark 2.5.2는 데스크톱 **Obsidian 1.8.9 이상**이 필요합니다.
- HWPX·HTML·PDF에는 Python, pypandoc-hwpx 또는 Pandoc 설치가 필요하지
  않습니다.
- Pandoc은 DOCX 생성과 사용자가 명시적으로 요청한 실제 DOCX 미리보기에만
  선택적으로 사용합니다.

# HanMark 2.6.1 — PDF save, journal layout, and adaptive tables

HanMark 2.6.1 adds direct PDF saving, two-column journal layouts, and independent automatic table sizing. Requires Obsidian 1.8.9 or later on desktop.

macOS hardware validation was explicitly waived by the maintainer. Automated macOS CI remains required; real-device PDF saving on macOS is not verified.

- PDF output now generates a file directly. Choose **PDF로 저장**, then **파일로 저장** when the PDF is ready. No virtual PDF printer is required. **프린터로 인쇄** opens the existing native print dialog.
- Choose single-column, two-column A (full body-width figures), or two-column B (column-width figures). Both two-column modes place figures near their anchors and fill the remaining area with ordered text.
- **표 폭: 자동 / 한 단 / 본문 전체 폭** controls tables independently of figure mode. Automatic sizing compares real line boxes at both widths, keeps compact numeric tables narrow, and expands tables when wider cells materially improve readability. It never shrinks the font or truncates content.
- Table columns are sized from the complete table and frozen before row splitting. Headers repeat, leading headings follow the first fragment, and continuations stay on consecutive pages. Full-width tables have 4mm flow clearance; nested list and callout context is preserved. Oversized rows/headers use the existing vertical field layout.
- Explicit table leading and cell padding prevent cumulative row-position differences observed in the older Chromium 135 print engine.
- Column spacing defaults to 10mm, with 8/12mm alternatives. Oversized figures retain their aspect ratio and fit a fresh page; they are not sliced.
- **최상위 제목에서 새 페이지 시작** is an independent option, off by default. It excludes the cover title, groups consecutive headings, and drains pending figures before a new section.
- Settings migrate to v11 with automatic table width and the existing single-column layout as defaults. Theme libraries and the built-in cover remain intact.
- Refreshed audited XML/URI/server-parser, ZIP/image, and development-parser dependencies while retaining Kordoc 4.2.5.

## Validation

Run `npm run check`, `npm audit --omit=dev --omit=optional`, `npm run test:pdf-render`, and `npm run test:pdf-ui` (install Chromium with `npx playwright install chromium`). The renderer test covers A/B × three table widths × section breaks, checks per-source block/cell preservation and row order, stable column widths, anchor distance and continuation pages, text/figure/table overlap, and rereads each printed cell from the PDF at its expected position. The UI test checks save cancellation/retry, fresh user activation, and the native print action against an Obsidian UI stub.

`HANMARK_BROWSER_EXECUTABLE` selects an existing isolated test browser. For a private local fixture, `HANMARK_PDF_TEST_MARKDOWN` selects a Markdown file whose HTTP images are embedded read-only; generated PDFs stay in the ignored `test-artifacts/pdf` directory. This fixture runner is not the production Obsidian image loader.

The desktop PDF bridge depends on a capability supplied by Obsidian. Unsupported hosts receive an explicit message and retain native printing. Browser-only checks do not establish that a real macOS Obsidian save picker works.

The supplied overlap example was visually confirmed. Re-exporting the unchanged development baseline in current Chrome did not reproduce that exact artifact, so its host-specific cause remains unconfirmed. The separate older-engine row drift was reproduced and corrected; current/older browser output is covered by cell-boundary and PDF text checks.

The release workflow verifies the tagged source on Windows, macOS, and Linux before publishing the three attested Community assets: `main.js`, `manifest.json`, and `styles.css`.

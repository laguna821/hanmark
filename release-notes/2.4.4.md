# HanMark 2.4.4 — Reliable DOCX and unified export / DOCX 복구·통합 내보내기

## English

HanMark 2.4.4 fixes the Pandoc DOCX regression reported after 2.4.3 and replaces the long export form with one responsive four-format export center. Existing HWPX generation, embedded remote/Vault images, semantic HWPX templates, source patching, HTML export, Word templates, and toolbar commands remain available. The bundled HWPX engine stays pinned exactly to Kordoc 4.2.5.

### Reliable DOCX export and preview

- Leading Obsidian YAML frontmatter is removed before HanMark normalizes Markdown for Pandoc.
- Colons in titles, aliases, nested metadata, UTF-8 BOM, and CRLF line endings no longer become a merged invalid YAML line.
- HanMark's generated `hwp-source` callout is removed before conversion, while YAML examples and delimiter lines inside fenced code remain untouched.
- A note whose leading frontmatter has no closing delimiter now produces an actionable Korean error instead of Pandoc's opaque YAML parser failure.
- DOCX export and the actual-package DOCX preview share the same guarded byte-generation path, so the fix applies to both.

### Unified export center

- HWPX, DOCX, HTML, and PDF are now large cards in a responsive 2×2 grid. Narrow windows collapse to one column.
- The selected card follows the active light/dark HanMark toolbar palette.
- HWPX-specific template, quick/public-document/source-patch options appear only when HWPX is selected.
- DOCX keeps its optional Pandoc settings, Word template, and preview controls.
- After a Vault export, the dialog stays open and shows the saved path. **Show in folder** is offered only when HanMark can identify the newly written Vault file.
- Existing command IDs and HWPX/DOCX/HTML toolbar entry points remain compatible and open the same export center with the requested format selected.

### PDF is delegated to Obsidian

The PDF card opens Obsidian's native PDF export command and settings. HanMark does not implement a second PDF renderer, does not apply an HWPX or Word template to PDF, and does not claim that PDF pagination matches Hancom Office. Page breaks and appearance follow Obsidian's print styles.

### Capability disclosure

- HWPX and HTML use no external converter. PDF delegates to Obsidian's built-in command.
- Pandoc remains optional and runs only after an explicit DOCX export, Fast DOCX **Refresh**, or direct preview-mode selection.
- Optional Windows Word-to-PDF preview can invoke Microsoft Word only after the user requests it.
- **Show in folder** can invoke the operating system's file manager with the newly saved Vault result selected, only after an explicit click. It does not scan arbitrary folders or run in the background.
- HTTP(S) requests occur only for image URLs explicitly present in the note being previewed or exported.
- There are no accounts, analytics, telemetry, advertisements, payments, remote feature flags, or clipboard access.
- Sharp, ONNX, PDFium, OCR/ML, and other optional native modules remain excluded from installation and the startup bundle.

### Updating from 2.4.3

No HWPX or Word template migration is required. Existing settings and command IDs are preserved. Pandoc is still needed only for DOCX conversion and actual DOCX preview; HWPX, HTML, and native Obsidian PDF export do not use the Pandoc path.

Release assets are exactly:

- `main.js`
- `manifest.json`
- `styles.css`

## 한국어

HanMark 2.4.4는 2.4.3 이후 보고된 Pandoc DOCX 회귀를 고치고, 길었던 내보내기 화면을 하나의 반응형 4형식 센터로 바꾼 업데이트입니다. 기존 HWPX 생성, 원격·Vault 이미지 포함, 문서 스타일 템플릿, 원본 수정, HTML, Word 템플릿과 툴바 명령은 그대로 사용할 수 있습니다. 내장 HWPX 엔진은 정확히 Kordoc 4.2.5로 유지합니다.

### DOCX 내보내기와 미리보기 복구

- Pandoc용 Markdown을 정규화하기 전에 노트 맨 앞의 Obsidian YAML 프런트매터를 제거합니다.
- 콜론이 포함된 제목, 별칭, 중첩 속성, UTF-8 BOM과 CRLF 줄바꿈이 한 줄의 잘못된 YAML로 합쳐지지 않습니다.
- HanMark가 만든 `hwp-source` 안내 콜아웃은 변환 전에 제거하고, 코드 펜스 안의 YAML 예제와 구분선은 그대로 보존합니다.
- 맨 앞 프런트매터를 닫지 않은 노트에는 Pandoc의 불투명한 YAML 파서 오류 대신 해결 방법이 포함된 한국어 오류를 표시합니다.
- DOCX 내보내기와 실제 패키지 DOCX 미리보기가 같은 보호된 바이트 생성 경로를 사용하므로 두 기능에 모두 수정이 적용됩니다.

### 통합 내보내기 센터

- HWPX·DOCX·HTML·PDF를 큰 카드로 배치한 반응형 2×2 그리드에서 선택합니다. 좁은 창에서는 한 열로 바뀝니다.
- 선택한 카드는 현재 밝은·어두운 HanMark 툴바 팔레트 색을 따릅니다.
- HWPX 템플릿과 빠른 HWPX·공문서·원본 수정 옵션은 HWPX를 선택했을 때만 표시합니다.
- DOCX의 선택적 Pandoc 설정, Word 템플릿과 미리보기 제어는 유지합니다.
- Vault 내보내기가 끝나면 창을 닫지 않고 저장 경로를 표시합니다. HanMark가 방금 저장한 Vault 파일을 식별할 수 있을 때만 **파일 위치 보기**를 제공합니다.
- 기존 명령 ID와 HWPX·DOCX·HTML 툴바 진입점은 호환되며, 같은 내보내기 센터를 요청한 형식이 선택된 상태로 엽니다.

### PDF는 Obsidian에 위임

PDF 카드는 Obsidian 기본 PDF 내보내기 명령과 설정 창을 엽니다. HanMark가 별도의 PDF 렌더러를 구현하거나 HWPX·Word 템플릿을 PDF에 적용하지 않으며, PDF 쪽 나눔이 한컴오피스와 같다고 보장하지 않습니다. 페이지 구분과 모양은 Obsidian 인쇄 스타일을 따릅니다.

### 접근 기능 공개

- HWPX와 HTML은 외부 변환기를 사용하지 않습니다. PDF는 Obsidian 기본 명령에 위임합니다.
- Pandoc은 선택 사항이며 명시적인 DOCX 내보내기, 빠른 DOCX **새로 고침**, 또는 직접 미리보기 방식 선택 뒤에만 실행됩니다.
- Windows의 선택적 Word-to-PDF 미리보기는 사용자가 요청한 뒤에만 Microsoft Word를 호출할 수 있습니다.
- **파일 위치 보기**는 사용자가 명시적으로 누른 경우에만 운영체제 파일 관리자를 실행해 방금 저장한 Vault 결과를 선택합니다. 임의 폴더를 검색하거나 백그라운드에서 실행하지 않습니다.
- HTTP(S) 요청은 미리보기나 내보내기 대상 노트에 직접 적힌 이미지 URL을 가져올 때만 발생합니다.
- 계정, 분석, 텔레메트리, 광고, 결제, 원격 기능 플래그와 클립보드 접근이 없습니다.
- Sharp·ONNX·PDFium·OCR/ML 등 선택적 네이티브 모듈은 설치와 시작 번들에서 계속 제외합니다.

### 2.4.3에서 업데이트

HWPX 또는 Word 템플릿 마이그레이션은 필요하지 않습니다. 기존 설정과 명령 ID를 유지합니다. Pandoc은 DOCX 변환과 실제 DOCX 미리보기에만 계속 필요하며 HWPX·HTML·Obsidian 기본 PDF 내보내기는 Pandoc 경로를 사용하지 않습니다.

Release에는 다음 세 파일만 첨부됩니다.

- `main.js`
- `manifest.json`
- `styles.css`

# R-011 — `#D709D1`의 WCAG·체감 대비 역전과 대비 극성

- 상태: CONFIRMED
- 작성일: 2026-08-10
- 최종 갱신: 2026-08-10
- 기준 버전/커밋: HanMark 2.5.6 후보 / `1359b80b3529c3e736bfe4c3ab7ed2141b6bf162`

- 해당 범위: PDF 테마 빌더의 `onKey` 자동 추천·대비 진단·미리보기, 작은 글자의 실제 화면 지각

## 1. 조사 질문

키 컬러 `#D709D1` 위의 검정 글자는 WCAG 2.2 대비가 `4.85:1`, 흰 글자는 `4.33:1`인데도 실제 HanMark 미리보기에서는 흰 글자가 더 또렷하게 보인다는 사용자 관찰이 나왔다.

이 차이가 단순 취향이나 막연한 색채 착시인지, 아니면 대비 공식·대비 극성·색 채널·글꼴 래스터화·사람의 시각 처리로 재현 가능한 현상인지 구분한다. 또한 “WCAG 기준 통과”와 “실제 화면에서 더 강하게 보임”을 제품이 어떻게 따로 표현해야 하는지 정한다.

## 2. 범위

### 포함

- `#D709D1` 배경과 `#000000`, `#FFFFFF`, `#182433` 글자색의 선언값 계산
- W3C 상대 휘도·대비 공식과 임계값 판정
- 대비 극성을 보존하는 `apca-w3` library 0.1.9 / base algorithm 0.0.98G-4g public beta 보조 계산
- 사용자 제공 검정·흰색 미리보기 PNG의 실제 glyph 픽셀 측정
- Weber 대비, CIELAB/OKLCH, 안티앨리어싱, ON/OFF 경로, irradiation, H–K 효과, 색수차의 설명력 비교
- 제품 문구와 향후 resolver 설계에 미치는 영향

### 제외

- 한 사용자의 관찰을 모든 사용자·모니터·인쇄물의 보편적 결과로 일반화
- APCA를 W3C 승인 기준이나 WCAG 3 확정 알고리즘으로 취급
- PDF 전체 접근성 준수 주장
- 사용자의 색각, 시력, 난시 또는 질환 진단
- R-008에서 확정한 수동 저대비 override 허용 정책 변경

## 4. 선언색의 정확한 계산

### 4.1 WCAG 2.2 판정

`#D709D1`의 상대 휘도는 `Y = 0.19245896583407207`이다.

| 글자색 | WCAG 대비 | 일반 글자 AA 4.5:1 | 큰 글자 AA 3:1 |
|---|---:|---|---|
| `#000000` | `4.8491793166814405:1` | 통과 | 통과 |
| `#FFFFFF` | `4.330629706300787:1` | 실패 | 통과 |
| `#182433` | `3.6215152723032853:1` | 실패 | 통과 |

계산 오류는 없다. WCAG 2.2는 밝은 색을 `L1`, 어두운 색을 `L2`로 다시 정렬한 뒤 `(L1 + 0.05) / (L2 + 0.05)`를 계산한다. 따라서 어느 색이 글자이고 어느 색이 배경인지, 즉 **대비 극성(contrast polarity)** 은 결과에서 사라진다.

검정과 흰색의 WCAG 비율이 같아지는 배경 휘도는 다음과 같다.

```text
(Y + 0.05) / 0.05 = 1.05 / (Y + 0.05)
Y = sqrt(0.0525) - 0.05
Y = 0.179128784747792
```

현재 배경은 이 경계보다 `0.013330181086280`만 높다. 따라서 검정이 WCAG 수치에서 이기는 것은 맞지만 차이는 약 12%이고, 그 값을 “검정이 사람 눈에 더 또렷하다는 지각 순위”로 해석할 수는 없다. W3C도 4.5와 3은 반올림하지 않는 **통과 임계값** 이라고 설명하며, 안티앨리어싱된 실제 획은 선언색보다 훨씬 흐릴 수 있다고 별도로 경고한다.

### 4.2 왜 흰색의 실제 경계 신호가 훨씬 큰가

배경과 글자 사이의 상대 휘도 변화는 다음과 같다.

| 글자색 | `Ytext - Ybg` | `abs(ΔY)` | Weber 대비 |
|---|---:|---:|---:|
| 검정 | `-0.192458965834` | `0.192458965834` | `-1.000000` |
| 흰색 | `+0.807541034166` | `0.807541034166` | `+4.195913` |

검정 획은 배경의 빛을 최대 100% 제거하면 끝이지만, 흰 획은 이 중간 휘도 배경보다 약 4.2배 큰 증가 신호를 만들 수 있다. 이것은 흰색이 보편적으로 더 읽기 쉽다는 뜻이 아니라, **이번 배경에서 두 자극의 물리적 크기가 애초에 같지 않다**는 뜻이다.

`#D709D1`의 선형 RGB 휘도 기여는 빨강 `0.144471`, 녹색 `0.001954`, 파랑 `0.046034`이다. 녹색 채널은 거의 비어 있다. 흰색으로 갈 때 추가되는 `ΔY ≈ 0.807541` 중 약 `0.713246`, 즉 약 88%가 사람의 명소시 휘도 감도가 큰 녹색 항에서 나온다. 반대로 검정으로 갈 때는 주로 빨강과 파랑 성분을 제거하지만 이 역시 합산되어 `ΔY ≈ -0.192459`의 명도 신호를 만든다. 작은 글자의 고주파 윤곽이 색채 채널보다 명도 채널에 더 의존한다는 연구와 일관되므로, 흰색의 더 큰 명도 edge가 현저성을 높였을 가능성이 있다. 이 색쌍에서 해당 채널의 인과적 기여량을 직접 측정한 것은 아니다.

Weber 대비는 여기서 국소 자극의 크기를 비교하는 보조 진단이다. WCAG 통과값을 대체하지 않으며, 읽기 속도·오독률을 직접 예측하는 단일 제품 점수로 사용하지 않는다.

### 4.3 다른 수치 모델과의 대조

| 모델 | 검정 | 흰색 | 해석 |
|---|---:|---:|---|
| WCAG 2.2 | `4.849:1` | `4.331:1` | 검정이 근소 우세; 일반 글자 임계 판정은 검정만 통과 |
| `apca-w3` 0.1.9 | `+36.516 Lc` | `-73.068 Lc` | 서로 다른 극성 부호를 유지하며 `abs(Lc)`가 `36.5` 대 `73.1`로 산출 |
| `abs(ΔY)` | `0.192459` | `0.807541` | 흰색 증가 경계가 약 4.196배 큼 |
| CIELAB `abs(ΔL*)` | `50.976` | `49.024` | 거의 동률, 검정 근소 우세 |
| CIEDE2000 | `48.383` | `46.987` | 검정 근소 우세이나 작은 글자 가독성 판정 용도가 아님 |

이 APCA 구현은 글자와 배경의 순서를 보존하고 normal/reverse polarity에 다른 비선형 곡선을 사용하므로 사용자 관찰과 같은 방향을 낸다. 그러나 Lc의 산술 비를 곧바로 사람 지각의 “몇 배”로 단정하지 않는다. 또한 APCA는 현재 W3C 규범이 아니다. W3C의 Silver 대비 자료는 비활성·미승인·비규범 상태이고, 2026년 WCAG 3 Working Draft도 최종 대비 알고리즘이 아직 결정되지 않았다고 명시한다.

## 5. 실제 12px glyph 측정

두 PNG의 같은 문구는 모두 184×12 px bounding box였다.

| 측정 | 검정 glyph | 흰색 glyph | 흰색/검정 |
|---|---:|---:|---:|
| 배경과 다른 픽셀 수 | 1,512 | 1,539 | `1.018` |
| 완전 전경 core 픽셀 | 333 | 342 | `1.027` |
| 안티앨리어싱 edge 픽셀 | 1,179 | 1,197 | `1.015` |
| 모든 glyph 픽셀 평균 `abs(ΔY)` | `0.135152` | `0.504407` | `3.732` |
| edge만 평균 `abs(ΔY)` | `0.118966` | `0.417797` | `3.512` |
| 전체 `sum(abs(ΔY))` | `204.350` | `776.282` | `3.799` |

bounding box는 같고 렌더 면적·core·edge 픽셀 수 차이는 약 1~3%뿐인데, 흰색의 캡처 sRGB 상대 휘도 경계 신호는 3.5~3.8배다. 따라서 사용자가 흰색을 더 즉각적으로 강하고 또렷하게 느낄 수 있는 **실제 렌더링 신호의 차이**가 존재한다. 이를 단순한 기분이나 취향으로 환원하면 안 된다. 다만 이 수치는 스크린샷의 픽셀값에서 계산한 것이며, 사용자의 패널에서 방출된 절대 광량을 광도계로 측정한 값은 아니다.

가장자리에는 검정 쪽 `(35,0,0)`, `(0,0,74)`, 흰색 쪽 `(252,255,255)`, `(245,240,255)`처럼 단일 알파 혼합선으로 설명되지 않는 채널별 fringe가 있다. 이는 채널별 서브픽셀 처리와 일관된 raster 흔적이지만, 두 캡처의 viewport와 subpixel phase가 같지 않으므로 렌더러·캡처·감마의 개별 기여는 분리하지 못했다. 작은 획의 약 78%가 edge 픽셀이어서 그 조건에 따라 결과 크기가 달라질 수 있다. W3C 선언색 계산은 의도적으로 이 렌더러별 결과를 규범 판정에 포함하지 않는다.

## 6. 기전별 판정

### 6.1 직접 확인됨

1. **WCAG와 실제 지각 질문의 목적 차이**
   WCAG 계산은 정확하지만 통과 임계 판정이다. 글자 크기·굵기·극성·래스터 획의 상대적 현저성을 연속 순위로 완전히 설명하지 않는다.

2. **두 자극의 국소 휘도 변화가 같지 않음**
   흰색의 선언색 `abs(ΔY)`는 검정보다 4.196배이며, 실제 캡처 glyph의 총 `abs(ΔY)`도 3.799배다.

3. **최종 glyph가 순수 HEX 두 점만으로 구성되지 않음**
   캡처에는 채널별 안티앨리어싱 fringe가 있고, 실제 edge 픽셀 신호도 흰색에서 3.512배 크다.

4. **대비 극성을 보존하는 대안 모델은 반대 방향을 냄**
   `apca-w3` 0.1.9는 검정 `+36.516 Lc`, 흰색 `-73.068 Lc`를 산출한다. 같은 RGB 입력을 다른 공식으로 계산한 보조 진단이므로 독립 실험이나 규범 대체가 아니라, 사용자 관찰과 방향이 일치하는 대안 모델 결과다.

### 6.2 강하게 뒷받침되지만 단일 기여량은 미확정

1. **명도 채널과 색채 채널의 공간 대역폭 차이**
   작은 글자의 고주파 형태는 저대역인 색채 채널보다 명도 채널에 더 의존한다. 녹색이 거의 없는 magenta에서 흰색은 녹색 휘도 항을 크게 켜지만 검정은 주로 빨강·파랑을 제거한다.

2. **irradiation과 ON 경로의 neuronal blur**
   밝은 획은 어두운 획보다 넓고 굵게 보일 수 있다. 이는 흰색의 “눈에 띔”을 강화할 수 있지만 세부 공간 분해능까지 더 좋다는 뜻은 아니다.

3. **렌더러·감마·패널 의존성**
   작은 glyph의 대부분이 edge 픽셀이므로 OS, 브라우저, 확대율, 디스플레이 서브픽셀 구조에 따라 결과의 크기는 달라질 수 있다.

### 6.3 주원인으로 보기 어려움 또는 현재 증거 불충분

1. **고채도 magenta 자체의 H–K 착시**
   Helmholtz–Kohlrausch 효과는 고채도 색이 같은 측정 휘도의 무채색보다 더 밝게 보일 수 있음을 설명한다. 그러나 배경이 더 밝아 보인다면 보통 검정과의 차이를 키우고 흰색과의 차이는 줄이는 방향이므로, 이번 흰색 우위를 단독으로 설명하지 못한다.

2. **일반적인 positive-polarity 우위의 단순 적용**
   검은 글자·밝은 전체 화면은 동공 축소와 공간 분해능 때문에 장문 읽기에서 유리할 수 있다. 하지만 이번 A/B는 넓은 배경이 동일하고 작은 글자만 바뀌므로 전체 화면 휘도와 동공 조건이 거의 같다.

3. **OFF 경로가 더 정밀하다는 사실의 단순 적용**
   같은 물리적 대비라면 어두운 표적이 더 정밀하게 처리되는 경향이 있다. 이번 두 자극은 국소 대비 크기부터 약 1 대 4.2로 다르므로 이 효과만으로 검정을 승자로 정할 수 없다.

4. **개별 사용자의 색수차·시력**
   눈의 색수차, 동공, 안경과 패널 스펙트럼은 추가 영향을 줄 수 있지만 현재 자료만으로 특정 기여를 진단할 수 없다.

## 7. 결론

사용자의 관찰은 “개인 취향”이나 “눈의 착각일 뿐”이 아니다. 가장 직접적인 설명은 다음 세 층의 결합이다.

1. WCAG 2.x는 선언색의 규범적 임계 판정을 위해 대비 극성을 버리는 대칭식을 사용한다.
2. `#D709D1`은 녹색 휘도 성분이 거의 없어 흰 글자가 만드는 국소 명도 증가가 검정의 감소보다 약 4.2배 크다.
3. 실제 12px 래스터 glyph에서도 흰 획의 휘도 edge 신호가 약 3.5~3.8배 크며, 밝은 획의 확대감이 현저성을 더할 수 있다.

따라서 검정은 **“WCAG 2.2 일반 글자 4.5:1 최소선을 통과하는 자동값”** 이고, 흰색은 **“일반 글자 최소선에는 0.16937 부족하지만 이 화면의 지각·래스터 신호는 더 강한 수동값”** 이다. 어느 설명도 “모든 사용자에게 검정/흰색이 더 잘 보인다”로 일반화하지 않는다.

또한 “눈에 더 빨리 띔”, “획이 더 굵어 보임”, “작은 글자를 더 적게 오독함”, “장문을 오래 읽기 편함”은 서로 다른 종속 변수다. 첨부 화면은 첫 두 항목의 물리적 근거를 제공하지만, 오독률과 장문 독해 성능은 통제 실험 전에는 확정하지 않는다.

## 8. 제품 결정에 미치는 영향

### 즉시 적용할 해석 계약

- WCAG 2.2 계산과 4.5/3/7 임계값, 반올림 금지 판정은 유지한다.
- 자동 검정을 “가장 잘 보이는 색”, “체감상 가장 안전한 색”이라고 표현하지 않는다.
- 정확한 표현은 “WCAG 2.2 일반 글자 최소선 통과”다.
- 수동 흰색은 R-008 계약대로 저장·출력을 허용하고 `4.33:1 · 일반 글자 기준 미달 · 큰 글자 기준 통과`를 계속 표시한다.
- APCA를 표시한다면 “실험적 화면 지각 참고값”으로 명확히 분리하며 WCAG 통과와 합치거나 대체하지 않는다.
- 이 연구는 사용자가 진행 중인 실제 테스트 결과를 받기 전 자동 resolver를 변경하는 근거로 사용하지 않는다.

### 후속 설계 후보

| 후보 | 장점 | 위험·검증 조건 |
|---|---|---|
| 실제 크기의 검정/흰색 A/B 샘플을 나란히 표시 | 초보자가 규범값과 자기 화면의 체감을 함께 판단 | 단순 선호를 읽기 성능으로 오인하지 않도록 문구 필요 |
| `onKeySmall`과 `onKeyDisplay` 내부 역할 분리 | 작은 문구는 4.5:1, 큰 제목은 3:1과 지각 신호를 따로 최적화 | 같은 면의 두 글자색이 디자인상 어색할 수 있음; UI 옵션은 늘리지 않아야 함 |
| 글자가 놓이는 `keySurface`만 미세 보정 | 원 키 컬러는 swatch/accent로 보존하면서 흰 글자도 4.5:1 가능 | “사용자가 고른 키 컬러 자체는 바꾸지 않는다” 계약과 역할 경계를 명확히 해야 함 |
| WCAG + 보조 지각 충돌 진단 | `규범 판정: 검정 / 화면 지각 참고: 흰색`처럼 사실을 숨기지 않음 | APCA의 비규범 상태, 버전 고정, 번들·Review 영향 검토 필요 |

예를 들어 text-bearing surface를 `#D300CE`로만 아주 조금 어둡게 하면 흰색 대비가 약 `4.505:1`이 된다. 이는 가능성을 보이는 계산 예시이며 확정 제품값이나 자동 변경 결정이 아니다.

## 9. 확정 실험 계획

한 화면의 관찰에서 각 기전의 기여량과 실제 읽기 성능을 분리하려면 다음을 기록한다.

1. 같은 글꼴, weight, 문구, 100% 확대율, 주변광에서 검정/흰색 순서를 무작위화한다.
2. 미리 알려진 색 선호가 아닌 작은 글자 식별 정확도와 오독률, 응답 시간을 측정한다.
3. 별도로 “더 빨리 눈에 띔”, “더 굵어 보임”, “더 편안함”을 평가해 식별 성능과 섞지 않는다.
4. 100%와 200%, Windows와 macOS, 최소 두 디스플레이에서 반복한다.
5. Obsidian 미리보기, Chromium 인쇄 미리보기, 저장 PDF 100%, 실제 종이 인쇄를 분리한다.
6. 각 캡처에서 글자 bounding box, core/edge 픽셀 수, 평균·합계 `abs(ΔY)`를 다시 계산한다.
7. 큰 제목과 12px 전후의 kicker·tag를 따로 검사한다.

보편적 흰색 우위, H–K 효과의 주도성, 색수차 또는 개인 시각 특성은 이 실험 없이 확정하지 않는다.

## 10. 구현과 테스트 영향

- 예상 변경 파일: 현재는 없음. 사용자 실제 테스트 완료 후 별도 결정으로 `src/io/editorialPdfTheme.ts`, `src/ui/EditorialPdfThemeManagerModal.ts`, `styles.css`, 관련 테스트가 후보가 된다.
- 유지해야 할 불변조건: 내장 2.5.5 출력 exact regression, 자동 `onKey >= 4.5`, 수동 override 저장·출력 허용, 실제 비율 경고, 잘못된 HEX 차단
- 새 테스트 후보:
  - `#D709D1`에서 WCAG 자동값 검정과 수동 흰색의 정확한 판정
  - 규범 판정과 보조 지각 판정의 충돌 상태
  - small/display token을 도입할 경우 실제 font size별 4.5/3 임계값
  - text-bearing surface 보정 시 원 key 불변과 최종 양자화 후 재검사
  - Windows/macOS 미리보기 캡처의 glyph edge 회귀는 환경 의존성이 커서 필수 unit test가 아닌 release characterization으로 관리
- 보안·권한: 새 파일·네트워크·clipboard·process 권한을 요구하지 않는다.

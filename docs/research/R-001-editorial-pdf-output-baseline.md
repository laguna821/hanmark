# R-001 — 첨부 Editorial PDF 출력 기준선

- 상태: CONFIRMED
- 작성일: 2026-08-10
- 최종 갱신: 2026-08-10
- 기준: 사용자가 제공한 HanMark PDF 출력물과 화면 캡처
- 관련 문서: R-002, R-003, R-004

## 1. 조사 질문

2.5.6에서 PDF 템플릿을 바꾸기 전에, 현재 사용자가 보고 있는 2.5.5 계열 출력의 페이지 구조, 고정 문구, 실제 색상, 반복 헤더·푸터를 정확히 기록할 수 있는가?

## 2. 증거와 조사 방법

원본 파일은 저장소에 포함하지 않았다. 개인 경로와 문서 본문을 공개 문서에 남기지 않고 동일성을 확인할 수 있도록 해시와 구조만 기록한다.

| 증거 | 확인값 |
|---|---|
| PDF | 5,379,154 bytes, SHA-256 6e11858bfcda0ad6440fc820ac9d5631dc5f904dcb9a1de493e147d03d36df2c |
| 캡처 1 | 785×99 RGBA, SHA-256 f998e5887eda359244a4156e5ec1d92950919f7c95c38ae0ea042ab85a9964c2 |
| 캡처 2 | 764×120 RGBA, SHA-256 27b79d7325f4c3d218ef96f46b60cafcaffcf10e510d8a0ad5c76e4470f5bdce |
| 캡처 3 | 1021×534 RGBA, SHA-256 4df24b79631fae4833eb000596099550909544852412d33875d731b0f056745e |

조사 절차:

1. PDF 메타데이터, 페이지 박스, 회전, 암호화, 페이지 리소스를 확인했다.
2. 모든 페이지를 래스터 렌더링해 접촉 시트와 대표 페이지를 육안 비교했다.
3. 벡터 path의 채움색·경계·좌표를 집계했다.
4. 세 캡처를 PDF의 같은 위치와 교차검증했다.
5. WCAG 상대 휘도 공식으로 주요 색 조합의 대비를 계산했다.

## 3. 확인된 PDF 구조

| 항목 | 관찰값 |
|---|---|
| 규격 | PDF 1.7, 23쪽 |
| 페이지 | 전 페이지 595.32×841.92pt, 약 210.02×297.01mm A4 |
| 회전/암호 | 회전 0, 암호 없음 |
| 생성기 | Microsoft: Print To PDF |
| 표지 번호 | 없음 |
| 본문 번호 | 물리 PDF 페이지 번호 2~23 |

표지는 상단 색 면과 하단 흰 면으로 나뉜다. 실제 상단 색 면은 y=0~438.36pt, 전체 높이의 52.07%다. 이는 소스의 52/48 설계와 일치한다.

본문 2~23쪽에는 같은 장식이 반복된다.

- 좌우 기준선: x=57.24~540.00pt, 약 20mm 여백
- 상단 실선: y=50.16~51.00pt
- 하단 실선: y=791.76~792.60pt
- 실선 길이: 482.76pt, 약 170.31mm
- 실선 두께: 0.84pt, 약 0.296mm
- 좌상단 고정 문구, 우상단 말줄임 문서 제목
- 좌하단 고정 문구, 우하단 페이지 번호

23쪽 접촉 시트 육안검사에서는 본문과 헤더·푸터의 충돌이나 잘림을 발견하지 못했다. 표지 제목은 이 문서에서 세 줄로 줄바꿈됐고, 우상단 본문 제목은 말줄임 처리됐다.

## 5. 실제 팔레트

| 역할 | 색 | 관찰 사용처 |
|---|---|---|
| Key | #002E6E | 표지 상단, 태그, 제목, 헤더·푸터, callout·코드·표 헤더 |
| Body ink | #182433 | 일반 본문 |
| Muted key | #31537D | 표지 보조 문구, 일부 보조 텍스트 |
| Accent | #00B5AD | 위·아래 실선, 일부 장식 |
| Paper/on-key | #FFFFFF | 종이와 어두운 면 위 글자 |
| Light accent | #7FE2DC | 코드상 callout label 등 |
| Highlight | #C7F1EE | mark 배경 |
| Border | #D9E0E6 | 표·인라인 코드 경계 |
| Alternate | #FAFAFA | 표 줄무늬·인라인 코드 배경 |

PDF 벡터 집계에서는 #002E6E, #182433, #31537D, #00B5AD, #FFFFFF가 지배적이었다. 캡처에서 청록 선이 더 연한 값으로 보이는 부분은 0.84pt 선의 안티앨리어싱 혼합색이다. 회색 뷰어 배경은 PDF 자체 색이 아니다.

캡처 1 아래쪽의 별도 네이비 선은 최종 PDF의 본문 헤더 벡터에는 없다. 다른 미리보기 단계, 다른 버전 또는 crop 인접 요소일 수 있으므로 2.5.6 출력 규격으로 채택하지 않는다.

## 6. 대비 기준선

| 조합 | 계산 대비 |
|---|---:|
| #002E6E / #FFFFFF | 13.00:1 |
| #182433 / #FFFFFF | 15.68:1 |
| #31537D / #FFFFFF | 7.88:1 |
| #00B5AD / #FFFFFF | 2.56:1 |
| #7FE2DC / #002E6E | 8.55:1 |
| #182433 / #C7F1EE | 12.88:1 |

현재 네이비 중심 설계의 주요 텍스트는 높은 대비를 가진다. 청록선은 흰 종이와 2.56:1이다. 현재 출력에서 장식으로 볼 수 있으므로 이 사실만으로 접근성 위반이라고 단정하지 않는다. 다만 사용자가 항상 식별돼야 하는 구조적 선으로 요구한다면 3:1 안전 목표가 필요하다.

## 7. 사용자 정의에 직접 영향을 주는 관찰

현재 #002E6E 하나가 두 가지 상반된 역할을 동시에 한다.

1. 큰 면의 어두운 배경
2. 흰 종이 위 제목·헤더 글자

이 구성은 어두운 네이비라서 두 역할이 모두 안전하다. 밝은 노랑 #FFD400으로 단순 치환하면 노랑/흰색 대비가 약 1.43:1이어서 흰 글자도, 흰 종이 위 노랑 글자도 읽기 어렵다. 반면 #182433 글자는 #FFD400 배경에서 약 10.96:1이다.

따라서 사용자는 키 컬러 하나만 고르더라도 렌더러 내부에서는 적어도 배경용 key, 그 위 글자 on-key, 흰 종이 위 key-ink, 선용 accent-line을 분리해야 한다. 이는 R-004의 핵심 설계 근거다.

## 8. 빈 문구의 출력 의미

- 일반 표지 문구와 헤더·푸터 문구가 빈 문자열이면 glyph만 사라지고 슬롯·간격은 유지하는 것이 사용자의 “빈칸” 기대와 맞다.
- 태그가 비면 빈 색 pill을 남기지 않고 pill을 숨긴다. 다만 태그 행의 예약 높이는 유지해 표지 레이아웃이 갑자기 움직이지 않게 한다.
- 우상단 문서 제목을 비우면 말줄임 기호도 없어야 하지만 실선은 유지한다.
- 좌하단 문구와 페이지 번호는 독립적이다. 문구를 비워도 번호를 유지할 수 있어야 한다.

## 9. 부수적으로 발견한 접근성·메타데이터 한계

이 특정 출력물에서는 텍스트 추출 결과가 0자이고 폰트 리소스가 없었다. 글자가 벡터 윤곽선이 되어 검색·선택·복사·스크린리더 읽기가 불가능했다. /Lang, 구조 태그, 북마크, 링크와 주석도 없었고 제목·작성자 메타데이터 일부가 깨져 있었다.

이는 Microsoft Print to PDF를 거친 이 한 파일의 관찰이다. HanMark 렌더러 자체가 모든 환경에서 항상 텍스트를 윤곽선화한다고 일반화할 수 없다. 2.5.6 커스텀 색상 범위와도 별개이며, 향후 PDF 접근성·메타데이터 조사는 새 R 문서로 분리해야 한다.

## 10. 한계

- 원본 Markdown과 실제 생성 당시 플러그인 데이터는 제공되지 않아 출력물과 설정을 역추적할 수 없다.
- 프린터 드라이버와 OS 색 관리가 실제 인쇄색에 영향을 준다.
- 래스터 캡처의 픽셀색은 안티앨리어싱 때문에 원래 CSS 값과 다를 수 있다.
- 육안검사는 대표 출력의 회귀 기준이지 모든 Markdown 구조의 조판 보증이 아니다.

## 11. 구현과 테스트에 미치는 영향

- 기본 프로필은 52/48 표지, A4, 기존 문구와 9색을 그대로 재현해야 한다.
- 사용자 변경 프로필은 밝은 색에서도 자동 전경색과 흰 종이용 ink를 만들어야 한다.
- 헤더·푸터와 표지 문구는 고정값과 동적값을 구분해 모델링해야 한다.
- 빈 문자열, 빈 태그, 문서 제목 모드, 페이지 번호를 서로 독립적으로 테스트해야 한다.
- 최종 수동 검증은 캡처만 보지 말고 실제 출력 PDF의 벡터색과 페이지 장식도 확인해야 한다.

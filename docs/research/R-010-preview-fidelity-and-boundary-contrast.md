# R-010 — PDF 테마 미리보기 충실도와 경계 대비 표현

- 상태: REQUIRED
- 작성일: 2026-08-10
- 최종 갱신: 2026-08-10
- 기준 버전/커밋: HanMark 2.5.6 후보 / 35bce95b5d7112f2b9d3d923a008c563db7ffa01
- 관련 문서: R-001, R-004, R-006, R-008
- 담당 범위: PDF 테마 빌더 미리보기, 키 면 글자 자동 추천, 대비 진단 문구

## 1. 조사 질문

실제 사용자 테마 PDF와 빌더 미리보기가 다른 원인은 무엇이며, `#D709D1` 위 검정과 흰색처럼 WCAG 최소선 부근에서 계산 결과와 개인의 체감이 다를 때 초보자에게 어떻게 정확하고 안전하게 안내해야 하는가?

## 2. 범위

### 포함

- 사용자 제공 녹색·자주색 테마 JSON과 실제 PDF 출력 대조
- 빌더 표지/본문 미리보기와 production renderer의 구조·색 토큰 대조
- `#D709D1`과 검정·흰색·본문 잉크의 반올림 전 대비 계산
- 자동 추천 불변식과 수동 override 안내 문구

### 제외

- 내장 `Achmage HanMark 기본` 출력 변경
- 키 컬러 자체의 자동 변형
- WCAG 2.2 색 대비 외 전체 PDF 접근성 적합성 주장
- APCA를 릴리스 판정 기준으로 도입하는 변경

## 4. 확인된 사실

1. 녹색 실제 PDF는 정상이다. 표지 상단 면과 하단 브랜드 문구에는 `#02653D`가 적용되며 페이지 1에 `#002E6E`가 사용되지 않는다.
2. 빌더 미리보기는 production renderer와 구조가 다르다. 실제 renderer는 표지 제목과 부제를 52% 키 면 안에 두지만 기존 미리보기는 제목을 흰 하단에 배치한다.
3. `file-title` 미리보기는 활성 노트 제목을 받지 않고 `프로젝트 회의 기록` 상수를 사용한다. 따라서 사용자 문구처럼 보이는 샘플이 반복된다.
4. 미리보기 제목은 `strong`, 시스템 문구는 `b`이며 해당 요소의 색을 명시적으로 격리하지 않았다. Obsidian 호스트 테마의 `--bold-color`가 적용되어 부모의 `keyInk` 대신 딥네이비로 보일 수 있다. 일반 `span`인 상세 문구만 녹색으로 보인 관찰과 일치한다.
5. `#D709D1`의 상대 휘도는 `0.1924589658`이다. 반올림 전 대비는 검정 `4.8491793167:1`, 흰색 `4.3306297063:1`, `#182433` `3.6215152723:1`이다.
6. WCAG 2.2 일반 텍스트 최소선은 4.5:1이고 경계값은 반올림해 통과시키지 않는다. 따라서 검정은 일반 텍스트 AA 최소선을 통과하고 흰색은 미달한다. 흰색은 3:1을 넘으므로 큰 텍스트 기준만 통과한다.
7. WCAG 2.x 대비값은 개인의 미적 선호나 특정 화면에서의 체감 선명도를 완전히 순위화하지 않는다. 글꼴 굵기, 안티앨리어싱, 디스플레이와 시각 조건 때문에 사용자가 흰색을 더 선명하다고 느끼는 것과 공식 최소선 판정은 동시에 참일 수 있다.
8. 기존 UI의 `toFixed(2)` 표시는 판정에는 영향을 주지 않지만, `#006FFB` 위 흰색처럼 실제 `4.499888:1`인 실패값을 `4.50:1`로 보이게 해 판정 문구와 모순될 수 있다.
9. 기존 Export 화면과 테마 목록 요약은 경고 개수 또는 단순 통과 문구만 표시해 수동 저대비 색의 실제 비율과 4.5–6.99:1 최소 통과 구간을 전달하지 못한다.
10. 기존 본문 미리보기의 단독 `code` 샘플은 `softTint/bodyInk`를 사용하지만 실제 PDF 코드 블록은 `keySurface/onKey`를 사용한다. 따라서 키 면 위 검정·흰색의 체감을 미리보기에서 직접 확인할 수 없다.

## 5. 해석과 결정

1. 미리보기는 별도 예시 디자인이 아니라 production renderer의 의미 구조를 축소해 보여줘야 한다. 표지 상단/하단 52:48, 문구 위치, 색 토큰 역할을 동일하게 맞춘다.
2. `file-title`은 빌더를 연 시점의 활성 노트 basename을 사용한다. 활성 노트가 없을 때만 `현재 노트 파일명`이라는 명시적 자리표시자를 사용하며 저장 데이터에는 넣지 않는다.
3. 미리보기의 모든 굵은 요소는 HanMark 미리보기 범위에서 `keyInk` 또는 `onKey`를 명시해 호스트 `--bold-color`를 차단한다.
4. 자동 `onKey`는 4.5:1 하드 게이트를 유지한다. `#D709D1`에는 검정을 자동 추천하며 계산을 체감 선호에 맞춰 뒤집지 않는다.
5. 흰색 수동 override는 기존 제품 계약대로 저장·출력을 허용한다. 다만 `4.33:1 — 큰 글자만 기준 통과, 일반 글자 기준 미달`로 계속 경고한다.
6. `4.5–6.99:1`을 단순히 `통과`나 `안전`이라고 표현하지 않는다. `일반 글자 최소 기준 통과 · 높은 대비는 아님`으로 표시한다. 7:1 이상은 `높은 대비`, 3–4.49:1은 `큰 글자만 기준 통과`, 3:1 미만은 `낮은 대비`로 구분한다.
7. `accentLine`은 텍스트가 아닌 선·그래픽 기준 3:1로 별도 설명한다. `keyInk`의 HanMark 목표 7:1과 WCAG 일반 텍스트 최소 4.5:1도 구분한다.
8. 화면 표시 비율은 소수 셋째 자리까지 내림해 판정 경계를 넘겨 보이지 않게 한다. 판정과 resolver는 계속 반올림 전 원값을 사용한다.
9. 빌더 입력·진단뿐 아니라 테마 목록, 설정 요약, PDF Export 상태에도 대표 onKey 비율 또는 모든 실패 override의 실제 비율과 판정 이유를 표시한다.
10. 본문 대표 코드 샘플은 실제 PDF와 같은 `<pre><code>` 및 `keySurface/onKey` 조합으로 그려 키 배경 위 글자 선택을 표지와 본문 양쪽에서 확인하게 한다.

## 7. 한계와 미해결 질문

- 인쇄물의 실제 체감은 프린터, 종이, 디스플레이 미리보기와 글꼴 렌더링에 따라 달라진다.
- 4.5:1은 최소선이지 모든 사용자에게 충분하다는 보장이 아니다.
- APCA는 이번 2.5.6 판정 기준으로 사용하지 않는다. 향후 W3C 표준 상태와 제품 요구가 바뀌면 별도 R 문서로 조사한다.

## 8. 구현 영향

- 변경 예상 파일: `src/ui/EditorialPdfThemeManagerModal.ts`, `src/io/editorialPdfTheme.ts`, `styles.css`, 관련 테스트
- 유지해야 할 불변조건: 내장 2.5.5 renderer exact output, 선택한 키 컬러 불변, 자동 onKey 4.5:1 이상, 수동 저대비 저장 허용
- 마이그레이션: 설정 스키마 변경 없음
- 보안·개인정보: 활성 노트 basename은 로컬 미리보기에만 사용하고 저장·JSON·로그에 추가하지 않음

## 9. 검증 조건

- 자동 테스트: `#D709D1`의 정확한 세 대비값, 자동 검정 선택, 수동 흰색 경고
- 자동 테스트: `2.999…`, `4.499…`, `6.999…` 표시가 각각 다음 판정 구간으로 반올림되지 않음
- 자동 테스트: 미리보기에서 고정 샘플 제목 제거, 전달된 파일명 사용, 상단 제목/하단 브랜드 역할 순서
- 자동 테스트: host bold color가 있어도 미리보기 `strong`/`b`가 semantic token을 상속
- 자동 테스트: Export·테마 요약이 실제 비율을 포함하고 단순 통과 문구를 사용하지 않음
- 자동 테스트: 대표 코드 블록이 실제 PDF의 `keySurface/onKey` 조합을 사용
- 자동 테스트: `:has`, `!important`, raw CSS/HTML 입력을 재도입하지 않음
- 수동 테스트: 녹색 JSON과 자주색 JSON으로 표지/본문 미리보기와 실제 PDF를 나란히 확인
- 완료 기준: 녹색 미리보기와 PDF의 구조·의미 색이 일치하고, 검정 4.85와 흰색 4.33의 안내가 최소선과 체감 차이를 오해 없이 설명함

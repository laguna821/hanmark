# R-014 — PDF 직접 저장과 그림 재배치 구현 계약

- 상태: REQUIRED (사용자 결정 확정, 플랫폼 검증 진행)
- 작성일: 2026-09-15
- 기준: 2.5.6, 11649b84ef5983f78ec3a4cc1ed69ab7bd86e651
- 관련 연구: R-001~R-006, R-008~R-013

## 질문과 범위

가상 프린터 없는 PDF 저장, A/B 2단 조판, 독립된 절별 새 페이지 옵션을 구현한다. 표지·테마 계약과 다른 내보내기 형식은 보존한다.

## 확인된 사실과 증거

- 기존 서비스는 window.print()를 호출한다. macOS 신고는 인쇄창은 열리지만 PDF 프린터를 선택하지 못한다는 내용이며 원인은 미확정이다.
- 로컬 Obsidian 1.13.7/1.14.1 패키지는 호스트 @electron/remote를 사용한다. 이것은 지원되는 모든 Obsidian/OS에서 검증했다는 의미가 아니다.
- 긴 실제 Markdown 자료(419줄, 이미지 11개)의 Chromium 사전 출력은 1단 22쪽, CSS A 20쪽, CSS B 12쪽이었다. 이는 새 그림 재배치의 검증 결과가 아니다.

## 사용자 확정 결정 (R-013의 상충 제안 대체)

- 세 OS 모두 직접 PDF 저장을 기본 작업으로 제공하고 기존 프린터 인쇄를 보조 작업으로 유지한다.
- 기본 single, 가운데 간격 10mm(8/10/12 선택), 절별 새 페이지는 기본 꺼짐이다. 레이아웃은 테마 JSON과 분리한다.
- A는 전체 본문 폭, B는 한 단 폭 그림이다. 모두 현재·다음 페이지 안에서 그림을 재배치해 빈 공간을 줄인다. 본문 순서와 그림끼리의 순서를 유지한다.
- 본문·목록·인용·콜아웃의 독립 그림을 대상으로 하며 표 셀과 문장 속 아이콘은 문맥을 유지한다.
- 긴 그림은 새 페이지에 맞춰 비율 유지 축소한다. 세로 분할 제안은 폐기한다. 현재 페이지의 남은 공간에 맞추기 위한 축소는 하지 않는다.
- 표지 제외 본문 최상위 제목에서 새 페이지를 시작하는 독립 옵션을 제공한다. 연속 제목은 한 묶음이다. 이 옵션이 켜진 경우 절 경계 전에 보류 그림을 모두 배치한다. 꺼진 경우 현재·다음 페이지 제한 안에서 제목 뒤 본문도 앞 페이지 채움에 사용한다.

## 구현과 대안

PDF 전용 DOM 조판기로 페이지/단의 크기를 실제 측정한다. CSS span만으로 원문 위치를 고정하는 방식은 여백 축소 요구를 충족하지 않는다. 1단 기본 경로는 보존한다. 출력 어댑터에만 호스트 PDF API를 한정하고 파일 저장은 FileGateway로 수행한다. 호스트 보안 설정 변경, Node fs, 임의 DOM 코드 실행을 추가하지 않는다.

## 검증 및 미해결 게이트

- 실제 PDF의 텍스트 보존, 그림 11개, 경계·간격, 절별 새 페이지, 테마 회귀를 검사한다. 개인 자료는 저장소 밖에서만 사용한다.
- 설정 v9→v10, 취소·실패·중복 실행·종료·팝아웃 경로를 검증한다.
- 실제 macOS Obsidian에서 프린터 없이 저장·재열기, Windows/Linux 회귀, 최소/현재 지원 런타임 검증이 릴리스 게이트다. 로컬 Chromium 시험으로 이를 대신 완료 처리하지 않는다.
- 자동 검사: npm run check, npm audit --omit=dev --omit=optional, git diff --check.

## 구현 검증 기록

- Windows에서 전체 검사 통과: 단위 테스트 260개, lint/TypeScript/production bundle/Community/release consistency.
- Chrome 153 및 Edge 135에서 실제 자료의 6개 모드 조합을 출력했다. 표지 포함 1단 22쪽, A 18쪽, B 12쪽이며 절별 새 페이지를 켜면 각각 24/22/17쪽이다. 원본 해시와 이미지 11개를 보존했다.
- 실제 Chromium 레이아웃에서 단 폭, 본문/그림 겹침, 페이지 경계, 그림 순서 및 원문 anchor와 1쪽 이내 거리, 제목 묶음의 새 페이지 시작을 검사했다.
- 합성 경계 자료의 생성 PDF를 PDF.js와 pdfplumber로 다시 읽어 문단 시작/끝 표식 84개와 코드 줄 100개의 순서·완전성을 확인했다.
- 실제 export modal 소스를 호스트 UI stub과 함께 구동해 저장 취소/재시도, 사용자 클릭 activation, 다운로드 상태, native print 전에 modal 닫힘을 검사했다. 이것은 실제 Obsidian 호스트 시험을 대체하지 않는다.
- 미완료 릴리스 게이트: 실제 Obsidian(특히 프린터 없는 macOS), 최소 Chromium 131, Windows/macOS/Linux의 native 파일 선택기와 프린터 통합. 구성한 CI를 원격에서 실행하거나 릴리스를 게시하지 않았다.

## 사용자 출력 재검토 (2026-09-15)

- 사용자가 별도 원고로 출력한 네 PDF를 제공하고, 그림 배치가 정상으로 보이며 sections의 많은 페이지는 짧은 절 분량 때문이라는 평가를 남겼다.
- 기본 A 25쪽, 기본 B 24쪽, sections A/B 각각 81쪽이다. 네 파일 모두 PDF 이미지 객체 2개를 포함하며 이미지가 용지 밖으로 넘어간 경우는 검출되지 않았다. PDF Producer는 Skia/PDF m150이다.
- 기본 A/B의 전체 페이지 축소판과 sections의 대표 페이지를 시각 점검했다. sections의 짧은 페이지는 제목과 소량의 본문을 배치한 뒤 다음 절을 새 페이지에서 시작하는 계약에 부합한다. 조밀한 연속 문서에서는 기본 꺼짐을 유지한다.
- 이 검토는 해당 PDF의 페이지 구성과 그림 경계에 대한 추가 증거다. 원본과의 문자 단위 대조, 네이티브 저장 경로, macOS 실기 검증을 완료한 것으로 확대 해석하지 않는다. 개인 원고와 출력 PDF는 공개 소스에 포함하지 않는다.
- 배포 준비 상태를 조회했으며 원격 기본 브랜치는 여전히 2.5.6, 로컬 개발 브랜치는 2.6.0이다. 이 재검토에서 원격 push, tag, Release, 기본 브랜치 변경은 실행하지 않았다.

# R-008 — 이름 있는 PDF 테마 라이브러리 제품 계약

- 상태: CONFIRMED
- 작성일: 2026-08-10
- 최종 갱신: 2026-08-10
- 기준 버전/커밋: HanMark 2.5.5 / 728b2b3495822a667417561ba0d55f9ee3cf7733
- 관련 문서: R-003, R-004, R-005, R-006
- 담당 범위: HanMark 2.5.6 Editorial PDF 사용자 테마

## 1. 조사 질문

단일 PDF 설정안 대신 수정 불가능한 기본 테마와 여러 사용자 테마를 어떻게 저장·선택·공유하고, 자동 대비를 해치더라도 사용자가 명시적으로 고른 색을 어떻게 존중할 것인가?

## 2. 범위

### 포함

- 내장 `Achmage HanMark 기본` 테마와 이름 있는 사용자 테마 라이브러리
- Vault별 활성 테마 기억
- 키 컬러 기반 자동 의미 팔레트와 세 가지 수동 override
- 선택 테마 한 개의 JSON 가져오기·내보내기
- 표지·머리말·꼬리말 문구의 빈칸 의미

### 제외

- 원시 CSS/HTML/Markdown 템플릿
- 제목·코드·표 등 모든 요소별 색상 편집
- 노트별 테마 매핑과 저장하지 않는 일회용 테마
- 글꼴·A4 geometry·52/48 표지 비율 변경

## 3. 조사 방법과 증거

| 증거 | 유형 | 재현 또는 위치 | 신뢰도/한계 |
|---|---|---|---|
| 사용자 확정 응답 | 사용자 결정 | 2026-08-10 2.5.6 계획 대화 | 제품 의도에 대한 최종 근거 |
| 기존 HWPX 다중 템플릿 | 소스 | `src/io/templateLibrary.ts` | CRUD·활성 ID·중복 이름 선례 |
| 기존 Word JSON 공유 | 소스 | `src/ui/WordTemplateManagerModal.ts` | 사용자 동작 파일 경계 선례 |
| WCAG 기반 의미 색상 | 연구 | R-004, R-007 | 색 대비만으로 PDF 전체 준수를 주장할 수 없음 |

## 4. 확인된 사실

1. 사용자는 하나의 전역 PDF 설정이 아니라 수정 불가능한 기본 테마와 여러 사용자 테마를 드롭다운에서 선택하기를 원한다.
2. 사용자 테마 수에는 제품상 임의 상한을 두지 않는다.
3. 마지막 선택은 Vault별로 기억한다.
4. 테마 하나를 JSON 파일로 공유할 수 있어야 한다.
5. 기본 흐름은 키 컬러 하나에서 안전한 색을 자동 제안하는 방식이다.
6. 고급 화면에서는 `onKey`, `keyInk`, `accentLine` 세 역할만 수동 변경한다.
7. 유효한 HEX의 수동 override가 대비 목표를 통과하지 않아도 저장과 인쇄를 허용한다. 대신 실제 비율과 경고를 계속 표시한다.
8. `Achmage HanMark 기본`은 2.5.5의 문구·색·geometry를 재계산하지 않고 그대로 보존한다.

## 5. 확정 제품 계약

- 내장 ID는 `builtin:achmage-hanmark`, 사용자 ID는 `custom:${crypto.randomUUID()}`다.
- 내장 테마는 편집·이름 변경·삭제할 수 없다. 편집은 사용자 복사본 생성으로 해석한다.
- 사용자 테마는 생성·복제·편집·이름 변경·삭제할 수 있다.
- 활성 사용자 테마가 사라지거나 손상되면 내장 테마로 복귀한다.
- picker와 HEX 입력은 같은 canonical `#RRGGBB`를 편집한다.
- 자동 resolver 오류는 적용을 막고, 유효한 수동 저대비 색은 경고 후 허용한다.
- 각 수동 override에는 `자동 추천 적용`이 있어 저장값을 `null`로 되돌린다.
- 빈 문자열은 숨김 의도이며 element slot과 page margin box geometry는 유지한다.
- JSON에는 local ID, active 상태, 경로와 timestamps를 넣지 않는다. 가져오기는 항상 새 사용자 ID와 중복 없는 이름을 만든다.

이 문서는 R-004 6절의 “4.5:1 미만 저장·인쇄 불가”를 자동 계산 결과에만 적용하도록 좁힌다. 수동 override는 경고 후 허용한다. 또한 R-005의 단일 `editorialPdfTemplate` 설정과 일회용 Apply 흐름을 다중 named library로 대체한다.

## 6. 대안과 기각 사유

| 대안 | 장점 | 위험/기각 사유 | 재검토 조건 |
|---|---|---|---|
| 단일 전역 테마 | 구현이 작음 | 여러 조직·브랜드 테마를 오갈 수 없음 | 사용자 요구가 철회될 때 |
| 모든 의미 색상 개별 편집 | 최대 자유도 | 초보자 목표와 충돌, 오류 표면 급증 | 전문가 모드를 별도 제품으로 설계할 때 |
| 낮은 대비 강제 차단 | 접근성 수치 강제 | 브랜드 규정을 우선하려는 사용자 통제권 침해 | 법적 강제 프로필을 별도로 제공할 때 |
| 라이브러리 전체 JSON | 일괄 백업 | 충돌·덮어쓰기·부분 실패 UX가 복잡 | 별도 백업/동기화 기능을 설계할 때 |

## 7. 한계와 미해결 질문

- 실제 종이·프린터·컬러 프로필은 화면에서 계산한 sRGB 대비와 다를 수 있다.
- 사용자 테마 수에는 상한을 두지 않지만 Obsidian `data.json` 크기와 UI 성능은 회귀 테스트로 감시한다.
- 대비 경고가 있는 테마는 출력 가능하므로 제품 문구가 이를 명확히 설명해야 한다.

## 8. 구현 영향

- 신규 순수 테마/팔레트 모듈과 설정 v9 migration이 필요하다.
- Export Center와 Settings가 같은 라이브러리 서비스와 활성 ID를 사용해야 한다.
- PDF renderer에는 선택 테마 snapshot만 전달한다.
- JSON은 기존 사용자 명시 파일 게이트웨이를 재사용하며 새 네트워크·process·filesystem 권한을 만들지 않는다.

## 9. 검증 조건

- 내장 테마의 CSS·DOM·고정 문구·9색 exact 회귀
- 라이브러리 CRUD, 중복 이름, 활성 삭제 fallback, 저장 rollback
- 수동 저대비 override 경고와 저장/인쇄 허용
- JSON round-trip, 크기·schema·HEX·enum·길이 검증과 비덮어쓰기
- 키보드·focus·오류 안내·색상 외 상태 표시

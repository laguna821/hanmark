# R-003 — 초보자용 PDF 사용자 정의 요구와 UX 계약

- 상태: CONFIRMED
- 작성일: 2026-08-10
- 최종 갱신: 2026-08-10
- 근거: 사용자 요구, 3명 이상의 반복 질문, R-001 출력 분석, R-002 코드 조사
- 관련 문서: R-001, R-004, R-005, R-006

## 1. 조사 질문

컴퓨터에 익숙하지 않은 사용자도 현재 PDF 내보내기의 단순함을 잃지 않으면서 브랜드 색과 문구를 바꾸고, 밝은 키 컬러에서도 읽을 수 있는 결과를 얻으려면 어떤 조작만 노출해야 하는가?

## 2. 사용자 문제의 강도와 한계

확인된 사용자 신호:

- 현재 PDF export는 깔끔하고 사용성이 매우 쉽다는 반응을 얻었다.
- 초보 사용자 테스트에서도 반응이 좋았다.
- 최소 3명이 독립적으로 “PDF 키 컬러와 기본 문구를 완전히 바꾸거나 지울 수 있는가”를 질문했다.
- 표지뿐 아니라 2쪽 이후 상·하단 선, 헤더·푸터의 색과 문구도 바꾸고 싶어 했다.

이는 기능 후보를 정당화하는 강한 정성 신호다. 다만 정량 사용성 연구나 대표 표본은 아니므로 모든 사용자가 같은 고급 기능을 원한다고 일반화하지 않는다. 기존 단순 기본 흐름은 그대로 남아야 한다.

## 3. 해결해야 할 사용자 작업

사용자는 다음 문장을 이해하지 않아도 돼야 한다.

- H1은 어떤 색인가?
- code block 배경과 전경은 무엇인가?
- callout label은 어떤 색인가?
- table header와 mark의 색은 무엇인가?
- header rule과 footer rule은 각각 무엇인가?

대신 다음 정도의 작업만 수행한다.

1. 키 컬러를 마우스로 고르거나 6자리 HEX로 입력한다.
2. HanMark가 읽기 안전한 글자·제목·코드·선 색을 자동으로 만든 결과를 본다.
3. 표지와 헤더·푸터의 기본 문구를 바꾸거나 완전히 비운다.
4. 미리보기에서 표지와 본문 대표 조합을 한 번에 확인한다.
5. 적용해 이번 PDF를 인쇄하고, 원하면 기본값으로 저장한다.

## 4. 2.5.6 필수 범위

### 색상

- 키 컬러 한 개
- 마우스 color picker
- 같은 값에 양방향 연결된 #RRGGBB 입력
- 선·강조 색상의 자동 파생
- 필요할 때만 펼치는 선·강조 색상 수동 override
- 글자색과 배경색의 자동 대비 보정
- 실제 적용된 자동 파생색을 보여주는 대표 미리보기

### 표지 문구

- 상단 작은 문구
- edition
- 자동 문서 제목
- subtitle
- 하단 brand
- system 문구
- detail 문구
- 태그 목록

자동 문서 제목은 기본적으로 파일명을 유지한다. 직접 입력 또는 빈칸 모드는 선택적으로 제공할 수 있지만, 기본 동작을 바꾸지 않는다.

### 본문 페이지 문구

- 좌상단 header
- 우상단: 문서 제목 / 직접 입력 / 비움
- 좌하단 footer
- 페이지 번호 표시 토글
- 상·하단 선의 의미 색

### 조작 안전성

- Apply 전에는 저장값을 바꾸지 않는 draft
- 취소하면 설정 변화 없음
- 되돌리기는 모달을 열었을 때 상태로 복원
- HanMark 기본값은 factory draft로 복원
- 저장 실패 시 이전 설정 rollback
- 인쇄 시작 시 정규화된 immutable snapshot 사용

## 5. 권장 위저드

### 진입점

- Export Modal의 PDF 카드에는 현재 스타일의 작은 swatch와 “PDF 디자인 바꾸기”를 둔다.
- Settings Tab에는 “PDF 기본 디자인 편집” 진입점을 둔다.
- 툴바에 색상 필드를 직접 늘리지 않는다.

### 단계 1 — 색

- 키 컬러
- color picker
- #RRGGBB 입력
- “선·강조 색상 자동 맞춤”은 기본 활성
- 결과 배지: 자동 가독성 안전, 자동 보정됨, 입력 확인 필요
- 사용자는 on-key, key-ink 같은 내부 토큰을 보지 않는다.

### 단계 2 — 문구

- 표지 문구를 사람이 알아보기 쉬운 한국어 label로 묶는다.
- 헤더·푸터를 별도 접이식 묶음으로 둔다.
- 각 입력 옆에 “비우면 출력하지 않음”을 명시한다.
- 태그는 최대 개수와 글자 수를 제한하고 추가·삭제 버튼을 제공한다.

### 단계 3 — 확인과 적용

- 표지 52/48 축소판
- 본문 한 페이지 축소판
- 작은 header/footer와 선
- 제목, 링크, code block, table header, callout, highlight 표본
- 선택한 원색과 HanMark가 실제 글자에 적용한 보정색 swatch
- “이번 PDF에 적용”
- 선택 사항 “이 디자인을 기본값으로 저장”

전체 실제 Markdown을 매 입력마다 PDF service로 렌더링하지 않는다. 별도 경량 DOM 미리보기가 같은 palette resolver만 호출해야 한다.

## 6. 색상 UX 계약

### 기본 원칙

- 사용자가 지정하는 것은 브랜드 seed다.
- 큰 브랜드 면에는 가능한 한 입력한 key를 그대로 사용한다.
- 그 위 글자는 자동으로 밝거나 어두운 안전색을 선택한다.
- 흰 종이 위 제목·링크에는 key와 같은 계열이되 충분히 읽히는 key-ink를 자동 생성한다.
- 선은 흰 종이에서 식별되는 accent-line을 자동 생성한다.
- 전경색을 일반 옵션으로 노출하지 않는다.

### 가독성 배지

사용자에게 표준 용어를 외우게 하지 않는다.

| 내부 판정 | 초보자용 표시 |
|---|---|
| 모든 작은 텍스트 7:1 이상 | 매우 선명 |
| 모든 작은 텍스트 4.5:1 이상 | 읽기 안전 |
| 자동 조정으로 목표 충족 | HanMark가 글자색을 자동 보정했어요 |
| HEX 미완성·무효 | 6자리 색상값을 확인해 주세요 |

“AA/AAA”는 상세 설명에서만 보여줄 수 있다. 기본 화면의 핵심은 통과 여부와 자동 조정 결과다.

### 결정적 동작

동일한 설정은 OS, Obsidian theme, 입력 시점과 무관하게 같은 최종 #RRGGBB 토큰을 만들어야 한다. 브라우저의 color-mix 또는 화면 표시만 믿지 않고 TypeScript에서 계산한다.

## 7. 정확한 HEX 입력 계약

허용:

- #123ABC
- 123abc
- 앞뒤 공백

저장:

- 항상 대문자 #RRGGBB
- alpha 없는 opaque limited-sRGB

거부:

- #ABC
- #RGBA
- #RRGGBBAA
- rgb(...)
- 색 이름
- var(...)
- 세미콜론, URL, CSS declaration
- 제어문자

입력 중 #, #12처럼 아직 완성되지 않은 상태를 즉시 기본값으로 덮어쓰지 않는다. 마지막 유효 색으로 미리보기를 유지하고 aria-invalid와 짧은 설명을 표시한다. 유효해질 때까지 Apply와 인쇄를 막고, blur 또는 Enter에서 canonical 형식으로 정리한다.

## 8. 빈 문자열 계약

필드 없음과 빈 문자열은 다른 데이터다.

| 데이터 | 의미 |
|---|---|
| 필드 없음 또는 undefined | 기존 기본 문구 사용 |
| 명시적 빈 문자열 | 사용자가 문구를 삭제함 |
| 빈 태그 배열 | 태그 없음 |

렌더링:

- 일반 label이 비면 DOM 또는 @page 슬롯은 유지하고 glyph만 출력하지 않는다.
- 표지 빈 태그 pill은 만들지 않는다. 태그 행의 높이만 유지한다.
- 우상단을 비우면 말줄임 기호도 만들지 않는다.
- 좌하단을 비워도 페이지 번호는 독립적으로 유지한다.

현재 nonEmptyString helper를 PDF 문구에 쓰면 삭제한 문구가 기본값으로 부활하므로 금지한다.

## 9. 2.5.6에서 제외할 기능

- H1, H2, code, table, callout별 개별 색상
- raw CSS 또는 HTML 입력
- 사용자 JavaScript
- 사용자 font 업로드
- alpha/transparency
- page size, margin, 52/48 비율 편집
- Markdown frontmatter별 템플릿
- 여러 named template 관리
- HTML/HWPX/DOCX와 PDF theme 자동 연결

이 기능은 강력하지만 초보자 흐름과 보안·마이그레이션 범위를 크게 바꾼다. 필요하면 별도 사용자 조사와 새 R 문서가 선행돼야 한다.

## 10. 권장 문구 길이 제한

다음 값은 관찰 사실이 아니라 52/48 레이아웃을 보호하기 위한 초기 제안이다. 구현 시 한글·emoji grapheme 기반 fixture로 조정한다.

| 슬롯 | 제안 최대 |
|---|---:|
| cover kicker, edition | 각 48 grapheme |
| cover subtitle | 80 |
| cover brand | 64 |
| cover system | 48 |
| cover detail | 80 |
| 태그 | 최대 4개, 각 24 |
| header left | 32 |
| header right custom | 40, 출력 시 20 기준 말줄임 검토 |
| footer left | 48 |

개행·제어문자는 공백으로 정규화한다. 따옴표와 역슬래시는 DOM textContent에서는 그대로 텍스트로, @page content에서는 CSS 문자열 escape 후 사용한다.

## 11. 사용성 수용 조건

- PDF 내보내기를 처음 쓰는 사람은 커스텀 화면을 열지 않고 기존과 똑같이 인쇄할 수 있다.
- color picker 조작만으로 읽기 안전한 결과를 얻는다.
- HEX를 아는 사용자는 정확히 여섯 자리로 입력할 수 있다.
- 밝은 노랑을 골라도 code/table/callout의 글자가 사라지지 않는다.
- 흰 종이 위 노랑 제목이 그대로 묻히지 않고 같은 계열의 읽기용 색으로 자동 조정된다.
- 사용자가 모든 문구를 비워도 기본 문구가 되살아나지 않는다.
- 취소 후 이전 설정과 출력이 byte-level 설정 관점에서 바뀌지 않는다.
- 미리보기에는 선택색과 실제 보정색의 차이가 정직하게 보인다.

## 12. 한계와 후속 조사

- 3명 이상의 반복 질문은 우선순위 신호지만 정확한 필드명과 위저드 이해도는 prototype test가 필요하다.
- “완전 custom”이라는 표현이 page geometry나 font까지 포함하는지는 아직 확인되지 않았다. 2.5.6은 안전한 branding 범위로 정의한다.
- AAA 자동 보정의 제품 문구와 exact brand color 보존의 우선순위는 R-004의 수학적 제약을 따라야 한다.

# R-035 — 공문서 점검을 Kordoc 4.25.0 수준으로: 계열 통합, 정확한 자리, 편집기 밑줄, 내보내기 전 점검

- 상태: REQUIRED (구현·검증 완료, 6절의 미완 항목 제외)
- 작성일: 2026-11-18
- 기준 버전/커밋: `3.0.0-dev` 1c79c04 → 작업 브랜치 `m5-lint`, Kordoc 4.25.0
- 관련 문서: R-022(공문서 계약), R-029(엔진 이식), R-030(틀과 모양)
- 담당 범위: 점검 실행(`src/io/gongmunCheck.ts`), 점검 창, 편집기 밑줄, 내보내기 전 점검, 설정

## 1. 조사 질문

Kordoc 4.25.0이 더한 점검(표기법 규칙 7종, 예산 검산, 논리, AI 투 문체, `lintBlocks`의 블록·위치 응답)을 HanMark 점검 창에 들이면서, 지적한 자리를 사용자가 친 글의 정확한 범위로 가리키고 고치기·무시·편집기 표시까지 이어지게 하려면 무엇이 필요한가?

## 2. 확인된 사실 (4.25.0을 직접 실행)

1. `lintBlocks(blocks, opts)`는 지적마다 `block`(넘긴 id), `offset`·`length`(UTF-16), `category`(notation·munche·slop·logic·budget), `rule`, `severity`, `match`, `message`, `suggest`를 돌려준다. `block.text.slice(offset, offset + length)`가 `match`와 같다(이모지 ZWJ 묶음·결합 문자·보충 한자 뒤에서도 확인).
2. `suggest`는 두 꼴이다. "`틀린 글 → 고친 글`"(요일·한글 금액·산출근거·표 합계)과 "`예) …`" 같은 조언. 앞의 꼴만 그대로 바꿔 넣을 수 있다.
3. 표 칸을 `table: { id, row, col }`과 함께 넘기면 합계 검산이 표 단위로 돈다(`BUDGET_TOTAL_MISMATCH`: "350 → 300").
4. `numbers` 옵션은 IR 블록이 없으면 `checked: 0`이다. 노트 글만으로는 표-본문 수치 대조가 돌지 않는다.
5. 규칙 id는 대부분 실행 중에 만들어져 배포본에서 목록을 뽑을 수 없다(문자열로 박힌 것은 10개뿐).
6. 악의적 입력: 20만 자 한 줄 + 표 좌표 (100000, 10000) 칸을 넘겨도 7ms에 끝났다(4.24.1·4.20.0 수정 확인).
7. 2.7.x 창은 `lintGongmunText`·`lintMuncheText`를 본문 전체에 돌려 줄 번호만 받았고, 고칠 때 그 줄에서 `match`를 다시 찾았다(같은 글이 한 줄에 두 번 나오면 첫째를 고침).

## 4. 설계

- **노트를 그대로 블록으로 자른다.** 한 줄이 한 블록, 표는 칸마다 한 블록(`line`, `ch` 보관). 앞머리 속성, 코드 블록(Mermaid 포함), `%%`·`<!-- -->` 주석, `$$` 수식 블록, `![[…]]`만 있는 줄은 넘기지 않는다. 노트 조립과 내보내기 어댑터를 거치지 않으므로 되짚을 변환이 없다. 지적 범위 = `line`, `ch + offset`, `length`.
- **고치기**: "`match → 바꿈`" 꼴일 때만 버튼이 생긴다. 그 범위의 글이 점검 때와 같을 때만 바꾼다(다르면 거절하고 다시 점검).
- **모두 고치기**: 바꿈 글에서 공백·물결표·줄표·점을 뺀 나머지가 원래 글과 같을 때만 "기계적"으로 본다(`isMechanicalFix`). 요일·금액·합계를 바꾸는 제안은 사실 판단이라 묶어서 고치지 않는다. 규칙 id 목록이 아니라 바꿈 내용으로 가르므로 엔진 규칙이 늘어도 안전하다. 실제 문서에서는 해당 0건이었다.
- **무시**: 노트 속성 `공문_점검무시`(영어 별칭 `gongmun-check-ignore`)에 목록으로 저장한다. 항목은 규칙 id(그 규칙 전체) 또는 `규칙|걸린 글`(그 글만). 노트와 함께 옮겨진다.
- **시간 한도**: 블록 600개씩 잘라 돌리고(표는 자르지 않음) 1.5초를 넘기면 멈춘 뒤 "일부만 점검"이라고 알린다. 2만 자 넘는 줄은 건너뛴다. 40만 자 넘는 노트는 점검하지 않는다.
- **편집기 밑줄**: CodeMirror 6 장식. 기본 꺼짐, 명령과 상태 표시줄 항목으로 노트 보기마다 켠다. 글이 바뀌면 0.7초 뒤 점검하고, 조각 사이마다 쉬며, 그 사이 글이 또 바뀌면 버린다. 밑줄 위에 올리면 메시지·고치기·무시가 뜬다. 읽기 보기에는 표시하지 않는다.
- **내보내기 전 점검**: 설정(기본 꺼짐). 공문서 HWPX 내보내기와 여러 양식 내보내기 앞에서 한 번 돌려 "고칠 것"(엔진의 error)이 있으면 점검 창을 "그래도 내보내기"와 함께 연다. 여러 양식이어도 노트가 같으므로 한 번만 묻는다.
- **메시지**: 엔진의 한국어 문장을 그대로 보여 준다(2.7.0과 같음). 계열 이름·버튼·요약은 한/영 문구표를 쓴다.

## 6. 한계와 미해결

- 조립으로 들어오는 다른 노트(`![[…]]`)의 글은 점검하지 않는다. 이 노트에 친 글만 본다.
- 엔진 메시지는 한국어뿐이다. 규칙 id 목록을 뽑을 수 없어 영어 문장 대응표를 만들지 않았다.
- 표-본문 수치 대조(`numbers`)는 노트 글만으로 돌지 않아 넣지 않았다.
- "모두 고치기"는 기계적 제안이 있을 때만 보인다. 4.25.0의 띄어쓰기 규칙은 조언("예) …")만 주므로 지금은 거의 나타나지 않는다.
- 편집기 밑줄·상태 표시줄 항목·내보내기 전 점검의 연결부(`gongmunCheckController.ts`)는 실제 Obsidian에서 확인하지 않았다. 브라우저 검증은 창과 편집기 확장을 직접 구동한 것이다.
- 무시 속성을 쓰면 본문 줄이 밀릴 수 있어 창은 0.12초 뒤 다시 점검한다.
- 인라인 코드 안의 글도 점검 대상이다.
